# ln-rank v3.9.35 发布审计角色清单

本文件用于防止“做了这个，炸了那个”。每次输出 zip 前，必须按 12 个独立角色审查。

## 1. 发布资产审计员
- HTML 引用的 JS/CSS 必须真实存在。
- JS/CSS 不能是 HTML 回退页。
- active-assets、module-manifest、release-meta、VERSION 必须一致。

## 2. 架构可维护性审计员
- UI 一致性版本不得改主查询、数据、AI 调用、飞书、本地背景、211 背景、趋势逻辑。
- 新增样式必须收口到 token / component contract，不做散点补丁。

## 3. 主流程回归审计员
- 成绩输入、筛选、查看专业、结果卡片、加入自选、报告入口、单卡诊断入口必须保留。

## 4. 数据口径审计员
- 全站保持“当前基于辽宁 2025 物理类历史记录；2026 一分一段接入后按位次 / 等位参考窗口查看”的口径。

## 5. 高报口径审计员
- 禁止推荐、优势专业、王牌、强校、能上、稳、保底、捡漏、录取概率、就业保证等误导表达。
- 学校背景、博士点、学科评估不得直接写成本科专业结论。

## 6. 辅助功能边界审计员
- 省内背景、211 背景、趋势页是复核辅助，不抢主查询。
- 211 不做光环推荐；趋势不做预测；本地属性不做就业保证。

## 7. AI 输出审计员
- 家长正文不得出现 AI不可用、fallback、rules-only、命中已收录学科、行业特色相关、知识库依据等内部字段。
- 单卡诊断按“一句话判断 / 主要依据 / 现实提醒 / 需要核验 / 家长提醒 / 使用边界”展示。

## 8. 报告一致性审计员
- 报告顺序固定：概要判断、当前方案怎么看、前中后段快速确认、最终排序清单、本方案确认清单、数据和使用边界。
- 稍高目标 / 主要参考 / 稳妥补充统计必须同源。

## 9. 家长可读性审计员
- 页面要像向导：我在哪、先看什么、下一步做什么、哪些只是辅助、哪些必须人工核验。
- 文案短句、温和、准确，不把内部字段传给家长。

## 10. UI 一致性审计员
- 字体大小、色系、按钮主次、卡片密度、报告顺序、提示层级必须全站一致。
- 每个页面当前视角只允许一个最强主按钮。

## 11. 移动端行为审计员
- Android 小屏不横向滚动；按钮不挤压；长标题不竖排；报告和诊断不撑爆。

## 12. API / 错误体验审计员
- API 成功与失败都应返回 JSON；前端不显示 HTML、stack trace、Unexpected token 或 JSON parse error。
- 数据读取失败不得伪装成真实无结果。
