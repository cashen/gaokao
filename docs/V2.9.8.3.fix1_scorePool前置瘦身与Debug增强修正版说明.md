# V2.9.8.3.fix1｜scorePool前置瘦身与Debug增强修正版

## 版本定位

本版基于 `V2.9.8.3｜主线瘦身与漏斗式计算提速版` 继续修复。目标不是增加功能，而是针对 debug 报告中暴露的性能瓶颈做定点处理：`scorePool` 对过大的候选池做重计算，且 debug 信息无法继续拆分定位。

## 核心修复

### 1. scorePool 前置瘦身

Debug 报告显示：

- `loadedRows = 3755`
- `basePool = 3700`
- `filtered = 201`
- `scorePool = 9286ms`

说明系统在“只看真实命中”等状态下，仍然先对 3700 条候选做画像分、兴趣分等重计算，最后才剩 201 条。

本版调整为：

- 当开启“只看真实命中”且存在孩子兴趣方向时，先执行兴趣真实命中预过滤；
- 预过滤后再计算 `profileScore`、`confidence`、`interestSortScore`；
- 减少对明显不会进入结果池候选的画像/兴趣排序计算。

### 2. scorePool 内部耗时拆分

新增 debug 细分：

- `interestPreFilter`
- `scorePoolBreakdown.time.profileScore`
- `scorePoolBreakdown.time.confidence`
- `scorePoolBreakdown.time.interestSort`
- `scorePoolBreakdown.profileHit/profileMiss`
- `cacheStats`

以后不只知道 `scorePool` 慢，还能看到慢在兴趣预过滤、画像分、兴趣排序还是缓存未命中。

### 3. basePool 过滤统计增强

新增 debug 细分：

- `baseFilterStats.rows`
- `baseFilterStats.out`
- `baseFilterStats.exclusionStats`
- `baseFilterStats.filters`
- `baseFilterStats.family`

用于判断基础候选池为什么没有缩小。

### 4. Debug 页面增强

`/fenxi/debug.html` 增加：

- 深度细分输出；
- 设备信息；
- JS 资源概况；
- DOM 节点数；
- 旧逻辑状态；
- 刷新队列状态；
- 数据加载耗时。

新增按钮：`复制深度报告`。

### 5. 数据加载耗时采集

`loadJsonFile()` 增加 debug 记录：

- 文件名；
- fetch 耗时；
- JSON 总耗时；
- 数据条数。

用于区分“网络加载慢”和“计算慢”。

## 注意

本版没有改变招生规则、兴趣规则和 A/B/C 业务含义，只调整计算顺序和诊断信息。
