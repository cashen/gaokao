# V2.9.8.3.fix3｜兴趣模块减负、A/B/C轻量渲染与交互优先修正版

## 发版边界

本包仍为 fenxi-only update，仅包含：

- `fenxi/`
- `functions/`
- `docs/`
- `tools/`

不覆盖根目录首页。

## 本版解决的问题

根据 V2.9.8.3.fix2 的深度 debug 报告，主筛选 `scorePool` 已从秒级下降到毫秒级，但仍存在三类体验问题：

1. 孩子兴趣抽屉打开、勾选、关闭时仍有明显卡顿。
2. `renderPlanABC` 在少量候选下仍出现 1 秒以上渲染耗时。
3. 模块“下一步”跳转有时被候选刷新或渲染任务阻塞，鼠标感觉迟钝。

## 主要修复

### 1. 兴趣模块交互轻量化

新增：

- `interest-interaction-lite.v2983fix3.js`

处理：

- 捕获兴趣卡点击，先更新抽屉内选中状态。
- 阻止旧全局 click 代理重复处理同一次兴趣点击。
- “只看真实命中兴趣方向”切换不再由旧绑定直接抢跑，改为延迟刷新。
- debug 增加 `interestToggleBreakdown`、`interestActionBreakdown`、`interestManualOnlyToggle`。

### 2. scorePool 顺序调整

修改：

- `compute-pipeline.v2983.js`

处理：

- 如果开启严格画像缩水，先用 profile 缓存做 strict 预瘦身。
- 再执行兴趣真实命中预过滤。
- 避免“严格画像本会排除的大量候选”先进入昂贵的兴趣匹配。

新增 debug 字段：

- `strictPreInput`
- `strictPreOutput`
- `strictPre`
- `interestPreFilter.afterStrict`

### 3. A/B/C 轻量渲染

新增：

- `abc-light-ui.v2983fix3.js`

处理：

- 不再对全部 filtered 候选生成完整 A/B/C 决策卡模型。
- 先轻量选出 A/B/C 候选，再只渲染最终展示卡。
- 避免 A/B/C 渲染阶段重复生成重型标签、取舍、家长必读等内容。
- debug 增加 `abcRenderBreakdown` 与 `abcPick_A/B/C`。

### 4. 模块跳转交互优先

新增：

- `module-step-priority.v2983fix3.js`

处理：

- 点击“下一步”时优先执行滚动跳转。
- 不让模块跳转等待候选刷新或重渲染。
- debug 增加 `nextStepLatency`。

## 验证重点

部署后建议优先测试：

1. 输入成绩/位次后，页面是否能快速继续操作。
2. 点“下一步”是否立即跳转。
3. 打开孩子兴趣抽屉，连续勾选/取消是否不卡顿。
4. 切换“只看真实命中兴趣方向”是否不再卡死。
5. A/B/C 方案是否明显比 fix2 渲染更快。
6. `/fenxi/debug.html` 深度报告中重点查看：
   - `interestToggleBreakdown`
   - `interestPreFilter`
   - `strictPreOutput`
   - `abcRenderBreakdown`
   - `nextStepLatency`
   - `applyFiltersTotal`
