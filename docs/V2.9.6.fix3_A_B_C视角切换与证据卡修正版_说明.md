# V2.9.6.fix3｜A/B/C视角切换与证据卡修正版

本版基于 V2.9.6.fix2，只修 A/B/C 方案盘的两个问题：

1. A/B/C 分段切换不再重新计算方案桶，使用已缓存结果做 render-only 切换。
2. A/B/C 候选卡增加 2025 / 2024 投档证据、两年位次变化、与当前位次距离和入选理由。

## 关键改动

- 新增 `assets/candidate-card-view.v296fix3.js`：负责把候选记录转换成家长能读懂的证据卡信息。
- 更新 `assets/abc-view.v296fix3.js`：A/B/C 切换走 `render-only`，优先调用 `renderPlanABCViewOnly()`。
- 更新 `assets/plan-engine.v296fix3.js`：
  - 首次完整刷新时计算并缓存 A/B/C buckets。
  - 点击 A/B/C 时只换当前 panel，不重新 `pickSchemeBuckets`。
  - `planScore` 接入候选缓存，减少重复排序计算。
  - 主卡与备选卡增加证据区。
- 更新 `assets/app.v296fix3.css`：增加证据卡样式。
- 更新 `diagnostics.html`：增加 `LN_CANDIDATE_CARD_VIEW_V296` 检查。

## 不改动范围

- 不改 Pages Function 认证逻辑。
- 不改根目录首页。
- 不改数据源。
- 不改 A/B/C 业务含义：A 守底线，B 看专业，C 争上限。
- 不把孩子兴趣改成硬过滤。

## 验收重点

1. 输入访问凭证后工具可正常启动。
2. 诊断页模块全通过，尤其是：
   - `LN_ABC_VIEW_V296`
   - `LN_CANDIDATE_CARD_VIEW_V296`
   - `LN_PLAN_ENGINE`
   - `LN_APP`
3. 点击 A / B / C 按钮，按钮应立即切换，面板应流畅变化。
4. A/B/C 候选卡应展示：
   - 2025 分数 / 位次
   - 2024 分数 / 位次（没有则显示待核验/暂无可比）
   - 两年变化
   - 与当前位次距离
   - 为什么进入 A/B/C 的短解释
