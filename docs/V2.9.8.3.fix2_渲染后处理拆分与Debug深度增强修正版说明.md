# V2.9.8.3.fix2｜渲染后处理拆分与Debug深度增强修正版

## 发版目标

本版针对 V2.9.8.3.fix1 的 debug 报告继续修复：`scorePool` 已由 9 秒级降到百毫秒级，但 `applyFiltersTotal` 仍有约 5 秒未拆解耗时，且场景切换仍存在 3 秒级长任务。本版重点不是继续堆功能，而是把“渲染 / 后处理 / 诊断 / 数据加载”拆开观测，并修复旧诊断漏斗造成的重计算。

## 核心修复

1. `compute-pipeline.v2983.js`
   - 新增 `renderBreakdown` 深度细分。
   - 对 `updateCounts`、`renderPlanABC`、`renderCards`、`updateLive`、`updateGuideState`、兴趣摘要调度分别计时。
   - Debug 报告可以看到 `applyFiltersTotal` 中到底是哪一步慢。

2. `advisor-diagnosis-engine.v2982.js`
   - 不再调用旧 `buildFunnelV29473()` 全量重建漏斗。
   - 旧漏斗会重新遍历 DATA 并跑 `profileScore`，是场景和 A/B/C 渲染卡顿的重要来源。
   - 新诊断直接读取 `compute-pipeline` 的 `baseFilterStats`，只做解释层。

3. `app.v2983.js`
   - 场景切换增加 `scenarioBreakdown`，拆出 `renderBaselineSummary`、`qualificationSummary`、`profileInterestSummary`、`renderPlanABC`、`updateLive`、`renderLight`。
   - 方便后续判断场景卡顿到底卡在 A/B/C 还是诊断摘要。

4. `app.v2981.js` 与 `data-engine.v297fix2.js`
   - 首屏 JSON 加载由串行改为并行加载。
   - `loadJsonFile()` 的 fetch cache 从 `no-store` 改为 `default`，配合资源版本戳，减少重复打开页面时的加载成本。
   - 学科映射、别名、招生名复核、官方目录、研究生目录改为 `Promise.all` 并行。
   - 学校地域三件套也改为并行加载。

5. `/fenxi/debug.html`
   - 保留“复制诊断报告 / 复制深度报告”。
   - 深度细分中将出现 `renderBreakdown`、`scenarioBreakdown`、`advisorDiagnosis`、数据加载耗时等。

## 验证重点

部署后建议复现一次输入成绩、选兴趣、选场景，然后复制深度报告，重点观察：

- `scorePool`
- `renderBreakdown.renderPlanABC`
- `renderBreakdown.renderCards`
- `renderBreakdown.updateCounts`
- `scenarioBreakdown.renderPlanABC`
- `advisorDiagnosis.ms`
- 各 `dataLoad:* totalMs`
