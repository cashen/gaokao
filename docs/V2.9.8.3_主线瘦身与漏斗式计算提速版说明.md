# V2.9.8.3｜主线瘦身与漏斗式计算提速版

本版目标不是新增功能，而是把 V2.9.8.2 系列中逐步叠加的交互补丁和计算链路收口，恢复“分段载入 + 漏斗式筛选”的速度体验。

## 核心原则

- 输入成绩 / 位次后，只加载相关位次分段。
- 家庭底线只重建基础候选池。
- 学生画像只影响提醒顺序、家长必读和标签，不在抽屉内触发全量筛选。
- 孩子兴趣只在基础候选池上做匹配，不回到全量数据重算。
- 场景路径只调整 A/B/C 组织倾向，不重新筛选全量候选。
- 详细卡展开不触发筛选，只展示已有解释。
- 高报师诊断和兴趣命中统计延后、缓存、按需查看。

## 新增文件

- `assets/debug-runtime.v2983.js`：运行时诊断采集，记录版本、候选池、耗时、点击链、错误和长任务。
- `assets/compute-pipeline.v2983.js`：漏斗式计算管线，缓存基础候选池和画像计算结果。
- `assets/app.v2983.js`：唯一新版轻量协调层，替代 v2981fix1 / v2981fix2 / v2982 多层补丁加载。
- `assets/app.v2983.css`：主页面收敛样式，隐藏旧 profileAsk、mentorRules 和大号位次带宽卡。
- `debug.html`：一键复制诊断报告页面。
- `tools/validate-v2983-release.js`：发布包验证脚本。

## 重要调整

1. `index.html` 资源版本戳更新为 `2983-20260511`。
2. 主页面不再加载 `app.v2981fix1.js`、`app.v2981fix2.js`、`app.v2982.js`，避免多层 app 补丁重复协调。
3. `applyFilters()` 由 `compute-pipeline.v2983.js` 接管：
   - 先生成 `basePool`；
   - 再对 `basePool` 做画像、兴趣、排序；
   - 同一上下文下复用缓存。
4. 学生画像抽屉内选项变动只做摘要刷新和诊断记录，不触发全量候选计算。
5. 场景选择只重排 A/B/C 和轻量摘要，不回到 DATA 全量重算。
6. `debug.html` 可复制运行报告，减少后续问题描述偏差。

## 调试方法

部署后打开：

`/fenxi/debug.html`

建议先在主页面复现问题，再刷新 debug 页面，点击“复制诊断报告”后发送。

报告会包含：

- 当前版本戳；
- body class；
- JS 加载数量和失败脚本；
- 候选池数量；
- 最近动作链路；
- 各阶段耗时；
- 抽屉、遮罩、滚动状态；
- JS 错误和长任务。
