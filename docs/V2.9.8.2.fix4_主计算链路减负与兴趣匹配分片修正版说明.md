# V2.9.8.2.fix4｜主计算链路减负与兴趣匹配分片修正版

本版针对 V2.9.8.2.fix3 中“输入成绩后明显卡顿、点地域卡顿、兴趣抽屉选完后主页面卡死、只看真实命中无法操作”的问题做性能收口。

## 核心修复

1. `applyFilters()` 改成两段式：先做区域、预算、资格、关键词、学校层级等便宜过滤，再对剩余候选计算画像分、兴趣匹配和排序分。
2. 兴趣命中统计默认读取缓存，不再在兴趣摘要或抽屉卡片中同步全量 `aggregate()`。
3. 兴趣命中统计改为延后调度，主页面刷新后再更新缓存，避免抽屉点选时阻塞主线程。
4. 地域 chip 刷新节流提高到 800ms，连续点击只保留最后一次刷新。
5. `child-interest-change` 刷新延后到 900ms，减少抽屉关闭后的同步重算压力。
6. 禁用旧 `app.v2981fix1.js` / `app.v2981fix2.js` 对 `renderCards/renderPlanABC/updateCounts` 的重复 wrap，不再重复轻量渲染。
7. `app.v2982.js` 作为唯一轻量协调器，只对 `autoRefreshAsync/applyFilters` 做防抖后的后处理。

## 保持不变

- 继续保持 fenxi-only update。
- 继续隐藏旧 `profileAsk`、`mentorRules` 和大号位次带宽卡。
- 继续保留统一决策上下文、旧规则适配、高报师诊断解释层、家长必读、校区复核、详细卡稳定展开等能力。

## 建议测试

1. 输入成绩/位次后页面仍能滚动和点击。
2. 连续点地域，页面不应明显卡死，只在停顿后刷新。
3. 打开兴趣抽屉，连续选择/取消兴趣，抽屉不应卡死。
4. 关闭兴趣抽屉后，A/B/C 和详细候选可延后刷新。
5. 勾选“只看真实命中兴趣方向”后，页面应可继续操作。
