# Tongxue human reading flow v001

状态：执行中。目标分支：`fix/tongxue-human-reading-flow-v001`。基线：`main@94d2f6523eb52821ef4408a47f76785cc4140464`。

## 这次审计已经做了什么

本次不是只做“样式缓解”，而是把用户从 `ln-rank`、Tongxue 主站和专业路径之间的完整阅读链路作为一个故障面审计：

1. 核对生产站 `https://gaokao.powers.org.cn/tongxue/` 的学校直达、学校自主搜索、专业直达三种状态。
2. 在真实浏览器中复现了学校搜索结果仍保留巨大首屏 Hero、专业直达上下文以裸文本出现、专业路径丢失原始 `returnTo`/决策上下文的问题。
3. 对照 active runtime `tongxue-runtime-v159-r3968`、controller、search view、result view、`ln-rank` handoff、student-voice navigation、专业路径构建器，确认问题属于跨模块状态与表现层组合，不是单一 CSS 文件丢失。
4. 确认生产 CSS 未定义 `.decision-context-strip` / `.decision-context-return`，因此专业直达上下文确实以未设计的裸结构渲染。
5. 保留 T0 主干树完整性与静态数据完整性作为合并门槛；本次不修改招生数据、不修改用户个人数据、不删除旧运行时文件。

## 本 PR 的处理范围

- 将自主搜索成功后的首屏切换为紧凑搜索轨，保留搜索入口但移除重复的巨大品牌 Hero。
- 将跨模块上下文改成明确的“来源/范围/返回”上下文栏；学校级公开留言不会被误写成某个专业的证据，专业级留言明确标注跨学校范围。
- 将摘要和留言从多层仪表盘卡片调整为可连续阅读的结论行与证据流，同时保留来源、时间和证据边界。
- 从 Tongxue 专业体验进入专业路径时，继续传递安全的原始返回路径和决策上下文，避免用户回不到 `ln-rank` 原工作面。
- 修正专业路径校验脚本中滞后的运行时版本断言，并补足 PC、Pad、Android 以及上下文回传的浏览器验收。
- 每次代码/资源身份变更同步更新发布身份，避免旧缓存继续提供旧 UI。

不在本 PR：删除历史非 active runtime、重做全站共享 shell、改变招生数据或专业/学校事实、把学校公开留言解释为学校-专业定向评价。

## 断网/卡死恢复协议

断网时任务不依赖“记住上一步”，而依赖仓库内的检查点 `.codex/progress/tongxue-human-reading-flow-v001.json` 和本台账：

- 每个分支、提交、PR、CI、Preview、合并和生产核验的物质性转变后更新 `headSha`、状态、证据和失败原因。
- 任何恢复动作先读取检查点，再读取本地 `git status`、当前提交和远端对应分支/主干；以精确 SHA 对账，不按“可能已经完成”重复写入。
- 先从 `inProgress` 对应的第一项未完成步骤继续；已完成的测试和写入不重复执行，除非精确 SHA 或环境状态发生变化。
- 所有写入使用显式目标路径；不使用 `git add -A`，保留用户已有未跟踪文件 `ln-rank/v3.9.35-function-regression-matrix.json`。
- 推送、建 PR、合并或部署网络失败时，先查询远端状态和 Actions，再决定是否重试；重试前记录 `lastFailure`，防止重复 PR、重复提交或错误合并。
- PR 合并门槛是目标分支精确 SHA 的静态校验、浏览器验收、资源/数据完整性检查和部署成功；不能用“网络断了”替代审计证据。
