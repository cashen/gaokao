# 统一最低分查询入口 v001 开发计划

## 1. 任务目标

基于 `main@bdcb83cc27722e5d1b74d68c204f775ec524c5b3`，为三个现有用户路径补齐统一的辽宁最低分查询入口：

1. `/major-path/` 专业升学地图：查询当前专业在辽宁各校的最低投档分。
2. `/tongxue/` 同学·学校：查询当前学校在辽宁各专业的最低投档分。
3. `/tongxue/` 同学·专业：查询当前专业在辽宁各校的最低投档分。

本任务中的“招生”明确等同于现有 `ln-rank` 的最低分/最低投档分查询能力，不新增招生人数计划采集，不改变 2026 辽宁物理类确定性数据的事实边界。

## 2. 当前事实与问题

### 2.1 现有事实

- `ln-rank` 已经拥有专业查询、学校在辽专业查询、最低投档分和累计位次展示能力。
- `major-path` 当前主要负责专业含义、专业关系、本科到研究生方向和背景证据。
- `tongxue` 当前主要负责学校/专业学生体验、评论和专业解读。
- `major-path` 当前没有直达 `ln-rank` 专业最低分的入口。
- `tongxue` 学校详情当前没有直达 `ln-rank` 学校各专业最低分的入口。
- `tongxue` 专业详情当前没有直达 `ln-rank` 专业跨学校最低分的入口。

### 2.2 需要避免的误解

本项目当前展示的是：

- 2026 辽宁物理类投档记录；
- 每个学校/专业/项目对应的最低投档分；
- 对应累计位次。

UI 中可以使用“查最低分”，结果页必须说明“2026 辽宁物理类最低投档分”。不得把最低投档分写成招生人数、招生计划或泛化为保证录取结果。

## 3. 架构原则

### 3.1 唯一业务所有者

`ln-rank` 继续作为最低分事实、查询 API、排序、分页和结果展示的唯一业务所有者。

`major-path` 与 `tongxue` 只负责：

- 传递已经确认的专业/学校身份；
- 生成站内导航；
- 保留来源与返回路径；
- 使用统一入口 UI。

不得在这两个模块内复制最低分查询 API、缓存、排序或分页逻辑。

### 3.2 统一导航契约

新增一个共享的最低分导航契约/纯构建模块，具体路径以当前共享资源结构和 release manifest 审计结果为准，候选路径：

`shared/resources/admissions/admission-navigation.v001.js`

逻辑接口至少覆盖：

- `buildMajorMinScoreHref()`
- `buildSchoolMinScoreHref()`
- `buildAdmissionEntryModel()`
- `sanitizeAdmissionReturnTarget()`

该模块只生成链接和用户可见入口模型，不发起网络请求，不拥有业务数据。

### 3.3 身份优先级

专业：

`majorCode > canonicalMajorName > rawMajorName`

学校：

`stableSchoolEntityId > canonicalSchoolName`

禁止把 `admission:<school>` 等临时招生目录标识作为 Tongxue 学校实体传递。

模糊专业、多个专业候选和无法确认的学校必须 fail-closed：

- 不自动跳到可能错误的结果；
- 保留待确认状态；
- 或隐藏入口并显示清楚的确认提示。

### 3.4 返回路径

只允许站内返回路径，至少覆盖：

- `/major-path/`
- `/tongxue/`
- `/ln-rank/`

外部 `returnTo` 必须被拒绝并回退到安全默认路径。

## 4. 用户路径与目标行为

### 4.1 专业升学地图

用户路径：

`专业查询 → 专业解释 → 本科到研究生路径 → 查辽宁最低分 → ln-rank 专业查询`

入口文案建议：

- 主按钮：`查这个专业在辽宁各校的最低分`
- 辅助说明：`查看 2026 辽宁物理类投档记录、最低投档分和对应位次。`

入口放在专业路径主体之后、背景/来源说明之前，成为自然的下一步动作。

### 4.2 同学·学校

用户路径：

`学校同学体验 → 学校摘要 → 查这所学校各专业最低分 → ln-rank 学校查询`

入口文案建议：

- 主按钮：`查这所学校在辽宁各专业的最低分`
- 辅助说明：`查看该校在辽宁各专业的 2026 物理类最低投档分。`

学校查询结果必须展示各专业记录。若展示汇总最低值，必须明确为“当前筛选范围内最低投档分”，不得制造一个脱离专业和项目范围的学校统一门槛。

### 4.3 同学·专业

用户路径：

`专业同学体验 → 专业解读 → 本科到研究生路径 → 查专业最低分 → ln-rank 专业查询`

入口文案建议：

- 主按钮：`查这个专业在辽宁各校的最低分`
- 辅助说明：`查看辽宁各校 2026 物理类投档记录和对应位次。`

与专业地图入口使用同一共享组件，不再形成两套相似但不一致的展示。

## 5. 分阶段实施

### 阶段 A：基线与路线锁定

- 重新读取最新 main SHA、分支、PR、Actions、当前 release 和所有相关断点。
- 核对 `major-all` 与 `school-all` 实际 URL 参数解析和恢复逻辑。
- 核对现有专业 resolver、学校 identity resolver、returnTo sanitizer。
- 确认当前 `/api/major-bands` 与 `/api/school-majors` 的结果字段、分页和错误契约。
- 保存修改前的 PC、Pad、Android 页面行为证据。
- 若远端 main 已产生新提交，停止使用旧基线，重新建立任务基线并在本文件/断点中记录。

完成条件：所有导航参数来自当前代码事实，不依赖历史 PR 或猜测。

### 阶段 B：统一导航契约

- 创建共享纯函数模块。
- 使用当前 ln-rank canonical route builder 或现有解析器。
- 统一生成专业和学校两种入口模型。
- 统一处理代码、标准名、模糊名、学校实体 ID、返回路径和来源标识。
- 对外部返回路径、临时学校 ID、空身份和不确定身份执行 fail-closed。
- 增加契约单测和静态检查。

完成条件：三个页面不再各自拼接最低分 URL。

### 阶段 C：专业地图接入

- 在专业地图当前人类阅读顺序中增加最低分入口。
- 仅使用已确认的 canonical major identity。
- 不改变专业事实、研究生目录、关系图和背景证据 owner。
- 不在专业地图内部请求最低分 API。
- 完成入口的空状态、模糊专业和小屏展示。

完成条件：从专业地图进入后，ln-rank 自动打开专业查询且专业身份正确。

### 阶段 D：Tongxue 学校接入

- 在学校结果标题/摘要之后加入统一最低分入口。
- 优先使用稳定学校身份。
- 对旧的或无效的 `admission:` 标识使用标准学校名称安全降级。
- 不把来源站点临时实体传给学生评价 API。
- 保留学校上下文和返回路径。
- 完成学校无效、来源不可用、没有招生记录等状态的稳定展示。

完成条件：从任意同学学校详情进入后，ln-rank 打开对应学校各专业记录，不出现 invalid_entity 或错误学校。

### 阶段 E：Tongxue 专业接入

- 在专业结果区加入统一最低分入口。
- 与专业地图复用同一导航契约和 UI 组件。
- 专业代码存在时必须优先传代码。
- 专业名称存在歧义时不得静默选择错误专业。
- 保留“查看完整专业升学地图”作为知识路径，和最低分入口形成清楚的两种下一步选择。

完成条件：从同学专业页进入后，ln-rank 展示该专业在辽宁所有匹配学校的最低分。

### 阶段 F：ln-rank 上下文补强

- 专业查询结果顶部显示当前专业和查询范围。
- 学校查询结果顶部显示当前学校和查询范围。
- 明确展示“2026 辽宁物理类最低投档分”。
- 学校汇总最低值必须带“当前筛选范围内”边界。
- 保留每条记录的专业、学校、项目、分数和位次对应关系。
- 不改变现有排序、分页、候选召回和数据来源。

完成条件：用户从外部模块进入后，能立即知道当前查询对象和数据口径。

### 阶段 G：统一 UI 与多端适配

统一入口组件必须统一：

- 文案层级；
- 按钮样式；
- 箭头；
- 边框和圆角；
- 内外间距；
- hover/focus/disabled；
- 长文本换行；
- loading 和空状态；
- PC、Pad、Android 的布局行为。

设计要求：

- 每个页面只出现一个主要最低分入口；
- 不把技术名称、模式名或 API 名称暴露给用户；
- 不将来源说明挤进按钮；
- 不使用新建的设备专属业务分支；
- 不增加第二套卡片渲染系统；
- 不造成加载后的页面跳动或横向滚动。

## 6. 测试矩阵

### 6.1 静态和契约测试

- 所有新增/修改 JS 通过 `node --check`。
- 专业入口必须包含 `majorCode` 或明确的待确认状态。
- 学校入口必须使用 canonical school identity。
- 禁止 `admission:` 进入 Tongxue 查询身份。
- 禁止外部 `returnTo`。
- 专业 URL 不得误用 school-all。
- 学校 URL 不得误用 major-all。
- 入口不得在页面内部重复调用最低分 API。
- 人类文案审计必须通过。
- 架构 handoff 审计必须通过。
- main tree integrity 审计必须通过。

### 6.2 功能路径

1. 专业地图 → 专业最低分 → ln-rank 专业查询。
2. 同学·学校 → 学校各专业最低分 → ln-rank 学校查询。
3. 同学·专业 → 专业各校最低分 → ln-rank 专业查询。
4. 从 ln-rank 返回原页面。
5. 复制深链接重新打开。
6. 浏览器刷新后查询状态保持。
7. 模糊专业、专业歧义、无专业代码。
8. 学校实体失效但标准名称存在。
9. 空结果、API 失败、来源不可用。
10. 重复点击和弱网加载。

### 6.3 数据正确性

- 页面最低分与 API 记录字段一致。
- 分数和累计位次不发生错位。
- 学校摘要最低值等于当前筛选范围内记录的最小值。
- 专业查询翻页后学校 ID 并集与总计数一致。
- 不重复学校、不遗漏页、不改变既有全量召回。
- 普通项目、中外合作、专项项目的边界保持清楚。

### 6.4 浏览器与设备

至少验证：

- PC 1366；
- Pad 820；
- Android 390；
- Android compact 360。

每个设备验证：

- 入口可见；
- 入口可点击；
- 键盘/焦点可用；
- 长名称正常换行；
- 无元素重叠；
- 无横向溢出；
- 返回和刷新正常；
- 没有 page error；
- 页面稳定后不发生明显跳动。

## 8. 弱网和断网恢复协议

每个阶段完成后都要更新：

`.codex/progress/unified-min-score-navigation-v001.json`

断网恢复时严格执行：

1. 读取本断点文件。
2. 读取 PR 当前 head SHA、base SHA、draft/ready 状态和最新评论。
3. 读取远端 Actions、Preview、Production 状态。
4. 读取远端 main 当前 SHA；如果已变化，重新计算差异。
5. 对比本阶段已完成提交，禁止重复成功写入。
6. 从第一个未完成阶段继续。
7. 如果远端 head 已变化，以远端 head 为事实，不使用旧本地记忆。
8. 若测试失败，记录 run ID、job、step、原因和修复提交，再继续。
9. 只有最终 head SHA 的所有证据通过后才允许 Ready 和 merge。

本任务不依赖聊天上下文作为唯一状态；PR 描述、计划文档、提交信息和断点文件必须足以让下一次会话接管。

## 9. PR 闭环

- 使用独立分支，不直接写 main。
- 创建 Draft PR。
- 每阶段提交保持可追溯，提交信息写明阶段和版本。
- Draft 阶段完成本地静态、契约、浏览器和资源完整性测试。
- 等待 PR head 对应的 Actions 完成。
- 使用精确 head SHA 验证 Preview。
- Preview 的 PC、Pad、Android 结果必须对应同一 head SHA。
- 全部通过后才转 Ready。
- Ready 后若 head 变化，退回 Draft 并重新验证。
- 使用 `expected_head_sha` 合并。
- 合并后核验 main SHA、递归树完整性、关键 CSS 200、JS 资源、API、数据 SHA parity、Pages 和正式域名。
- 生产失败不能用重试掩盖，必须记录真实原因并修复。

## 10. Definition of Done

只有全部满足以下条件才算完成：

- 三个入口均可用；
- 三个入口均跳入正确的 ln-rank 查询模式；
- 专业和学校身份不串；
- 最低分和位次对应正确；
- UI 在 PC、Pad、Android 一致；
- 没有重复 API、重复缓存或第二业务 owner；
- 文案清楚表达“2026 辽宁物理类最低投档分”；
- 模糊和异常身份 fail-closed；
- 断网恢复可从 PR 和断点继续；
- 版本提升到 `v3.9.90.3 / v3990_3`；
- 所有相关 Actions、Preview、Production 检查通过；
- main 树完整性通过；
- 最终合并到 main；
- 合并后正式站和 Pages 实际路径验证通过。
