# T0 视觉资源树丢失事故记录（2026-08-28）

## 结论

本次属于 T0 / Sev-0 级别的生产可用性事故：核心页面仍返回 HTML，但共享 Shell、交互样式和页面 CSS 不再随主分支发布，访客看到浏览器默认样式，筛选入口处于不可用或持续加载状态。当前证据指向发布树完整性故障，不指向招生事实数据被改写。

## 根因

PR #245（`统一视觉系统与 PC/Pad/Android 响应式契约 v001`）的 head
`2416d476a7329317fab2e091d1938e8ee0283429` 只有 3 个递归文件，而合并前的
`main`（`6f3e24031f5db0fe1755cbeebe68413638a5be0e`）有 2394 个递归文件。
合并提交 `0e01dc4815748a4ab1290b98649edf88922bfb44` 接受了这个稀疏树，造成：

1. `index.html`、`.github/workflows`、`_headers` 以及绝大多数站点文件从 `main` 树中消失。
2. 页面 HTML 仍可返回，因此仅看部署成功或 HTML 状态码的检查没有阻断发布。
3. 核心 CSS 请求出现 404，页面退化为浏览器默认样式；这就是“CSS 都没了”的直接表现。

这是合并树级别的完整性缺口，不是单一 CSS 内容回归，也不是数据层查询故障。

  `391442235713d074f4f0f3d49b43ad8eab08916b`。
- PR #247 补齐恢复核验记录，合并提交：
  `09c40c2a7d919f7012ebce329781548140ed85a9`。
- 恢复后 `main` 递归树为 2398 个文件；事故前 2394 个文件全部存在，缺失数为 0。
- 6 个关键 CSS 资源均为 HTTP 200 且 `Content-Type: text/css`。
- `/api/ln-rank-runtime-health`、`/api/major-bands-health`、排名查询和分数等值查询均通过。
- 235 个 JSON 文件解析通过，非法 JSON 为 0。
- 生产静态数据 SHA-256 与当前 `main` 一致：2025 记录 10915 条、2026 记录 11628 条、学校索引 960 条、专业索引 802 条。
- 与事故前基线相比，`data/`、`analysis/`、招生筛选数据没有业务数据路径变更。

## 防复发规则（必须执行）

1. PR 目标为 `main` 时，合并前比较 base/head 的递归文件树；成熟树不得缩小到 base 的 90% 以下。
2. 合并前后必须存在入口、部署 workflow、release contract、`_headers`、2026 数据索引和关键 CSS sentinel。
3. `main` push 检查必须检查刚到达主分支的精确 SHA；部署绿色不等价于源码树完整。
4. PR head SHA 变化后，旧的检查证据失效；必须重新检查并用最终 SHA 合并。
5. 合并后必须复核主分支 SHA、文件树、关键 CSS 的 HTTP 状态和类型、runtime/API 健康、生产数据 SHA 对齐。
6. 任何允许大范围删除或恢复的例外，都必须在独立 PR 中明确说明基线、影响范围和回滚证据，不得通过删除检查或降低阈值绕过。
