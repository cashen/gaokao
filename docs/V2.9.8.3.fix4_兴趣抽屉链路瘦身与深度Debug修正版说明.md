# V2.9.8.3.fix4｜兴趣抽屉链路瘦身与深度Debug修正版

## 发版口径

本包仍为 fenxi-only update，仅包含：

- `fenxi/`
- `functions/`
- `docs/`
- `tools/`

不覆盖仓库根目录首页。

## 修复背景

V2.9.8.3.fix3 的 Debug 报告显示，主筛选链路已明显下降：`applyFiltersTotal` 约 238–456ms，`renderPlanABC` 约 3ms，`scenarioChangeLight` 约 16–17ms。但兴趣模块附近仍出现 4–7 秒长任务，用户感知为：打开孩子兴趣抽屉、点孩子想法、勾选兴趣、关闭抽屉均迟钝。

本版重点不再改主筛选，而是专门瘦身兴趣抽屉链路。

## 核心调整

### 1. 兴趣抽屉只做轻量点选

新增：

- `fenxi/assets/interest-drawer-slim.v2983fix4.js`

处理原则：

- 打开兴趣抽屉时只渲染静态兴趣卡、孩子说法卡和已选状态。
- 不在抽屉打开时计算真实候选命中。
- 不在抽屉内触发 A/B/C、详细候选和诊断重算。
- 关闭抽屉后统一调度一次刷新。

### 2. 覆盖旧 runtime 的重刷新入口

新版补丁覆盖：

- `toggleGroup`
- `toggleAuto`
- `undecided`
- `removeGroup`
- `handle`
- `refreshLight`
- `start`

兴趣卡点击只保存状态并更新 UI，不立即跑主候选计算。

### 3. 避免孩子说法旧链路触发重计算

新增 capture 级事件拦截：

- `[data-child-intent-id]`

点击孩子说法时直接调用轻量 `toggleIntentLite()`，并阻止旧 bind 链路继续运行。

### 4. 禁止兴趣命中统计在抽屉内同步跑

对 `LN_INTEREST_HIT_SUMMARY_V298.scheduleAggregate()` 做策略覆盖：

- 不在抽屉交互内同步执行真实命中 aggregate。
- Debug 中记录 `interestAggregatePolicy`。

### 5. Debug 增强

新增深度项：

- `interestDrawerOpenBreakdown`
- `interestDrawerRenderMs`
- `interestDrawerSelectionOnly`
- `interestToggleDeepBreakdown`
- `interestIntentToggleBreakdown`
- `interestAutoToggleDeepBreakdown`
- `interestFlushBreakdown`
- `interestAggregatePolicy`

后续定位兴趣模块卡顿时，可直接看上述字段。

## 验证

新增验证脚本：

- `tools/validate-v2983fix4-release.js`

验证项包括：

- VERSION 是否为 fix4
- index 版本戳是否为 `2983fix4-20260511`
- 是否加载 `interest-drawer-slim.v2983fix4.js`
- runtime 是否被轻量 toggle 覆盖
- UI renderDrawerBody 是否被轻量抽屉覆盖
- 孩子说法点击是否有 capture 拦截
- 是否记录兴趣抽屉深度 Debug
