# 模拟志愿工作台 v006 执行计划与交付记录

## 目标

把 `/ln-rank/simulation-report.html` 从“缩小版正式填报表”改成家庭志愿决策工作台：先收集考虑中的学校/专业，再逐条核对、调整顺序、家庭讨论，最后生成 PDF。

## 已执行

1. 页面第一任务改为“添加/整理志愿”，不再以九列表格作为移动端主界面。
2. 手机端使用志愿卡片；桌面端保持紧凑卡片结构，不把信息强行塞入横向表格。
3. 每条志愿允许暂时不完整；缺学校或专业只显示“未完成”，不阻断继续整理。
4. 增加整体状态摘要：总条数、信息完整、需要核对、未完成。
5. 历史数据降为第二层信息；学校/专业是第一层，历史记录是参考事实。
6. “核对与提醒”改为按需展开的核对区，不再占据主视觉。
7. 家庭处理改为“待讨论 / 保留 / 备选 / 已排除”，避免重新引入“冲稳保”决策框架。
8. 调整顺序在移动端改为清晰的上移/下移按钮；删除带确认，明确不会影响正式填报。
9. 支持 URL 入站契约 `school / majorCode / majorName`，并在重复内容存在时提示已在哪一条志愿。
10. 保留现有 v001 数据控制器和 v005 PDF 能力作为兼容层；v006 只重构用户可见的信息架构，避免重复实现招生历史与 PDF 数据逻辑。
11. 增加 v006 静态契约测试和 GitHub Actions。
12. 增加 `simulationWorkspaceVersion: simulation-workspace-v006` 与 `simulationWorkspaceRevision: r052-human-decision-workbench`，满足本次修订的独立版本追踪。

## 验收标准

- 首次打开 5 秒内能理解下一步是“添加/放入志愿”，而不是“填写一张表”。
- Android/Pad 不需要横向滚动才能完成主要任务。
- 空白志愿可以先保留，系统不制造“必须填满”的压力。
- 调整顺序、删除、清空都有明确的人类可理解反馈。
- 历史数据缺失只作为“需要核对”的事实，不转化为录取结论。
- PDF 仍是最终输出，而不是页面核心操作。
- 正式填报与模拟整理明确隔离。
