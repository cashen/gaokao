## 1. 目标：让用户感觉“继续查”，而不是“离开后重新开始”

Tongxue 的行为目标不是增加入口数量，而是让每次跳转都保留三件事：

1. 我刚才在看什么对象（学校、专业、地区，是否已确认）；
2. 我为什么来到当前页（分数卡、专业路径、直接链接、分享）；
3. 我下一步可以做什么，以及怎样无损回到原来的查询。

### 人类行为判定原则

- **位置感**：任何结果页都要回答“我现在在哪、来自哪里”。
- **连续感**：跳转后对象、分数、专业、筛选条件、阅读位置不应凭空消失。
- **可逆性**：错误选择、误点和网络失败都要能回到上一步，不把用户推回首页。
- **低认知负担**：一个状态只给一个主要动作；确认只在身份确实不唯一时出现。
- **信任边界**：来源未取得时不补写；学生体验不伪装成官方事实；未知状态不显示成功语气。
- **可解释等待**：加载、缓存、断网、重试和外链打开方式都要让用户知道正在发生什么。
- **跨端一致**：PC、Pad、Android、Alook 的点击、键盘、返回、滚动和失败恢复采用同一行为合同。

## 2. 入口—出口全路径盘点

### 2.1 入口矩阵

| 入口 | 用户意图 | 当前行为 | 人类行为风险 | 目标行为 |
|---|---|---|---|---|
| `/tongxue/` 空首页 | 想先随便看看学校或专业体验 | 选择范围后输入 | 首屏范围、目录准备状态和输入对象的关系不够强 | 首屏明确“看学校/看专业”，输入提示随范围切换，准备态不遮蔽可理解动作 |
| `/ln-rank/` 学校卡 → Tongxue | 想验证一所学校的学生体验 | 自动带入学校并查询 | 直接交接等待期间可能像卡住；失败后来源不明显 | 显示“已带入：学校名 → 正在查公开体验”，提供立即更换/回来源入口 |
| `/ln-rank/` 专业卡 → `/major-path/` → Tongxue | 想先看升学路径，再看学生体验 | 带专业代码、专业名、主题和返回地址 | 进入专业结果后上下文被压缩；返回链可能被误认为回首页 | 结果顶端显示来源与专业口径，返回恢复原卡片和阅读位置 |
| 学校全部专业 / 专业全部学校 | 想从实体继续细看 | 进入学校或专业体验 | 学校实体、校区、专业范围容易在视觉上混为一谈 | 学校使用 canonical entity；专业明确“跨学校专业体验” |
| 地区搜索 | 想缩小学校范围 | 展示城市或学校选择卡 | 用户可能把地区卡误读为已选择学校 | 地区是中间筛选态，明确“请选择具体学校”，不自动选择 |
| 学校/专业简称或模糊词 | 想用自然语言快速找到对象 | 建议、确认、多候选 | 过度确认打断探索；候选太多时选择成本高 | 唯一高置信度自动继续；仅在真实歧义时确认，并显示差异理由 |
| 直接 URL（`school+entity`、`scope=major`） | 从外部或历史记录直接打开 | 解析并自动查询 | 无来源时用户不知道为何来到结果页 | 显示“直接打开/来自某模块”状态；安全返回无效时退化为模块首页，不伪造来源 |
| 分享链接 | 想把一所学校分享给别人 | 仅携带学校/实体 | 分享者可能以为会带上分数和筛选条件 | 明确“这是独立体验链接，不包含你的分数和筛选”；分享不继承私密上下文 |
| 浏览器刷新/前进/后退 | 想保留原位置继续阅读 | 由 URL 与 history 恢复 | 内部输入、确认和范围切换可能污染后退栈 | 只为完成查询建立历史节点；临时输入和展示状态使用 replace |

### 2.2 出口矩阵

| 出口 | 当前问题 | 目标合同 |
|---|---|---|
| `返回刚才的查询` | “刚才”可能是来源模块、上一个查询或同页上一步，语义不唯一 | 分成“回到来源查询”和“同学你好首页”两个出口；有安全 `returnTo` 才显示来源出口 |
| `/ln-rank/` 分数入口 | 结果页中的最低分链接使用当前 Tongxue URL 作为返回，可能形成循环 | 返回参数使用原始来源快照，恢复分数、专业、筛选和阅读锚点 |
| `换一所学校` / 换专业 | 直接结果时可见，普通结果时不够稳定 | 结果头部始终提供轻量“更换对象”，不清空原来源快照 |
| 浏览器 Back | 可能逐步退回输入词、歧义态和范围切换 | 完成查询是一个可回退节点；加载、重试、分页不新增历史节点 |
| 外部来源站 | `target=_blank` 在移动容器内体验不确定 | 文案明确“打开来源站（新页面）”；保留当前页，外链失败不影响当前结果 |
| 加载更多 | 失败后按钮改成“加载失败，点击重试”，但上下文和位置未显式承诺 | 原评论和阅读位置保持，重试只请求下一页；不可重复追加、不可跳到顶部 |
| 无结果/错误 | 有来源链接或技术诊断，但不总有回来源/更换入口 | 每个非成功状态都有“换对象”“回来源（若安全）”“重试（若可重试）”中的最小动作集合 |
| 分享/复制 | 当前分享刻意丢弃上下文，用户未必知晓 | 以独立入口语义展示，禁止暗示可恢复分享者私人查询 |

## 3. 当前代码的行为学问题与优先级

### P0：会破坏连续查询感或造成事实误导

1. **渲染后主动滚动可能抢走阅读位置**：`tongxue-runtime-search-view-v159.js` 的 `focusResult()` 在状态提交后对标题 `focus` 并 `scrollIntoView({block:'start'})`。初次提交可接受，但加载更多、重试、分页或异步专业资料更新时会造成视口跳动。应区分“用户刚提交”与“结果内部更新”。
2. **返回出口没有清晰区分来源返回与模块返回**：`decision-context-return` 目前统一使用“返回刚才的查询”，而 `/tongxue/` 顶部还存在固定的 `/ln-rank/` 返回入口。两个出口会让用户猜测哪个能保留筛选。
3. **原生导航兼容必须持续设为硬门槛**：跨模块入口在 Android/Alook 中不能只依赖脚本增强。所有高价值入口应先是可用的 `<a href>`，JavaScript 只做上下文增强；动态按钮需要等价的原生后备路径。
4. **来源不可用时必须 fail-closed**：`fetchExperience()` 已对网络错误、HTML、非法 JSON、无效模式和空评论做了边界处理；后续 UI 改动不得以“补充一个看起来合理的总结”掩盖空源或失败源。

### P1：功能可用，但不符合自然探索习惯

1. **结果页层级过长**：专业结果同时承载“专业解读、升学路径、学生留言、来源说明、技术信息”，用户很难判断第一步该读什么。
2. **专业页存在口径切换成本**：“跨学校专业体验”是准确的，但需要紧邻一句“不同学校学生的体验混在一起，不能代表某校培养情况”，否则用户可能拿它回答学校问题。
3. **直接交接的 12 秒等待缺少可控状态**：`tongxue-direct-handoff-v155.js` 会轮询查询按钮并自动点击。自动化符合既定意图，但用户需要看到已带入对象、当前阶段、失败后的人工入口和取消/更换动作。
4. **工程语言仍可见**：错误页的“技术诊断（供排查）”、页面版本和大量技术字段对普通用户不应成为主要视觉层；诊断应在 footer 或明确的“反馈问题”后置。
5. **临时状态可能污染后退栈**：`writeLocation()` 默认 push，范围切换、地区选择、歧义确认与完整查询混用历史策略。后退按钮应回到用户做过的决定，而不是回放每一次输入状态。
6. **上下文条带需更像“记忆提示”而非系统日志**：`decision-context-strip` 已建立，但需要更明确地突出对象、来源和唯一返回动作，避免长文本、窄屏换行和多条元数据争夺注意力。

### P2：细节影响可达性、信任和移动端效率

1. 顶部品牌目前是文本而非可点击链接；用户在结果页缺少一个稳定的“同学你好首页”锚点。
2. 结果页隐藏 hero 文案后，普通查询和直接查询的“我在哪里”差异较大；应使用一致的紧凑结果头。
3. 外链新页面、系统返回、Alook 内嵌浏览器、低高度手机的安全区与焦点环需要逐一验收。
4. “看学校怎么说/看专业怎么说”“公开体验/大学生怎么说”等标签需建立统一词表，避免同一动作多种称谓。
5. 长评论展开、加载更多、错误重试要满足键盘焦点不丢失、触摸目标不小于 44px、`prefers-reduced-motion` 不产生额外动画。

## 4. UI 目标方案

### 4.1 结果页固定骨架

结果页按以下顺序组织，且每层只承担一个问题：

1. **上下文条带**：`来自哪里 · 当前对象 · 当前范围`，若有安全返回显示“回到来源查询”；若没有则显示“这是独立查询”。
2. **结果头**：对象名称、学校/专业范围徽标、口径 chip、一个“更换对象”动作。
3. **先回答**：学校先看两件事；专业先看“专业是什么/怎么学/升学方向”，学生留言作为体验证据，不与事实混排。
4. **继续阅读**：评论列表、展开全文、加载更多；分页更新不得改变用户锚点。
5. **来源与边界**：一句人类可读的来源说明，随后折叠技术信息；来源站外链明确是否新页面。

### 4.2 三种关键状态

- **首次查询**：在用户提交后的短时间内把焦点移到结果标题；不覆盖用户正在输入的内容。
- **结果内部更新**：加载更多、重试、专业资料补全只更新局部区域，保持滚动、焦点和已读评论。
- **失败/空结果**：保留对象、输入、来源和已显示证据；给出一个主要下一步（重试或更换对象），并说明“这不是现实中没有体验”。

### 4.3 移动端优先细节

- 结果头和返回动作在首屏内可见，但不做会遮挡阅读的永久悬浮层。
- 上下文条带在 360px 宽度下最多三行，长来源名截断并可展开。
- 学校/专业确认卡一列排列，卡片整体可点，触摸目标 ≥44px。
- 评论卡不使用左右并列信息表达关键差异；日期、认证、评分为次级信息。
- 低高度屏幕优先保留对象、返回、更换和输入，不让品牌图占据主要视口。

## 5. 执行任务分解

### TX-00：基线、断点与不重复执行合同

交付：本计划、实施状态文件、每个阶段的证据链接和精确 HEAD SHA。

恢复顺序：

1. 读取本计划和最新状态/断点文件；
2. 读取当前分支、工作树、远程 `main` SHA；
3. 读取该 SHA 对应的 CI、Preview、Production 状态；
4. 从第一个未完成 TX 继续；
5. 网络或工具超时只记录为 `unknown`，先按精确 SHA 检索，不重复写入、提交或合并；
6. 任何无法读取的线上状态不得推断为成功，也不得把“未查询到”写成“没有”。

### TX-01：统一入口/出口合同

涉及：

- `shared/decision-context/decision-context.v001.js`
- `shared/decision-context/return-snapshot.v001.js`
- `shared/resources/experience/student-voice-navigation.v001.js`
- `shared/resources/schools/school-identity-center.js`
- `tongxue/share/tongxue-share-v130.js`
- `tongxue/app/tongxue-runtime-controller-v159.js`
- `/ln-rank/`、`/major-path/` 的现有入口工厂

动作：

- 为每个入口生成 `sourceSurface/sourceAction/returnTo/contextId/anchor`；
- 把“回来源”“回模块首页”“更换对象”做成互斥且可解释的动作层级；
- 返回快照保存分数、专业、筛选、结果模式和阅读锚点，但不写入长期家庭方案；
- 明确 share link 是独立查询，不复制个人分数、筛选或家庭上下文；
- 对学校实体始终走 canonical entity，非法 `entity` fail-closed 并给出可选的正式学校重新选择。

验收：所有安全返回均同源；无 `returnTo` 时不显示会造成错误期待的“返回刚才的查询”。

### TX-02：history、焦点和滚动策略

涉及：

- `tongxue/app/tongxue-runtime-controller-v159.js`
- `tongxue/app/tongxue-runtime-search-view-v159.js`
- `tongxue/app/tongxue-runtime-result-view-v159.js`

动作：

- 只在用户完成一个明确查询、选择一个明确对象或切换查询范围时建立历史节点；
- 输入中间态、加载、重试、加载更多、技术详情展开默认不 push；
- `focusResult({reason})` 增加原因策略：首次提交/直接交接可聚焦并滚动，局部更新只 announce，不滚动；
- 加入 `scroll-margin-top` 和移动端焦点回归测试；
- `popstate` 恢复状态时避免重复请求、重复 push 和旧请求覆盖新请求。

验收：在评论中段点击加载更多、展开全文、重试后，视口与焦点不跳到标题；浏览器 Back 一次返回上一个用户决定。

### TX-03：结果页 UI 重排与词表统一

涉及：

- `tongxue/index.html`
- `tongxue/app/tongxue-runtime-result-view-v159.js`
- `tongxue/app/tongxue-runtime-search-view-v159.js`
- `tongxue/app/tongxue-copy-v152.js`
- 相关共享 UI token 与导航样式

动作：

- 顶部品牌恢复为稳定的首页链接；结果页使用统一紧凑结果头；
- context strip 改为“来源/对象/返回”三段式，移动端最多三行；
- 专业页把事实、升学路径、学生体验分组，默认只展开最有助于下一步的一层；
- “技术诊断（供排查）”降级为后置 disclosure，普通错误先说用户能做什么；
- 建立统一词表：学校体验、专业体验、公开留言、来源站、回到来源查询、独立查询；
- 错误、空结果、目录失败状态保持对象和原输入，并提供最小可行下一步；
- 外链文案明确“打开来源站（新页面）”，不把外部来源当作当前页的继续状态。

验收：用户在 5 秒内能说出当前对象、当前范围、来源和下一步；不阅读技术详情也能完成返回、重试和更换对象。

### TX-04：直接交接、断网和 fail-closed

涉及：

- `tongxue/app/tongxue-direct-handoff-v155.js`
- `tongxue/app/tongxue-runtime-controller-v159.js`
- `tongxue/app/tongxue-runtime-result-view-v159.js`
- API response validation 与来源健康校验

动作：

- 自动交接显示确定性阶段：已带入对象 → 正在读取公开留言 → 已完成/暂时无法读取；
- 超时不显示“成功”，提供更换对象、回来源和稍后重试；
- 网络断开、HTML、非法 JSON、空评论、无效模式全部保持原输入，禁止模型或前端自行补写；
- 有上一份已验证结果时可保留并标注“上次取得时间”，新请求未成功前不覆盖；
- 第三方来源失败不阻断官方事实或模块导航，学生体验失败不伪装成“没有人评价”。

验收：断网、慢网、4xx、500、HTML、非法 JSON 六类故障均可解释、可恢复、无幻觉；请求取消后旧结果不覆盖新查询。

### TX-05：无障碍、移动端和浏览器容器

动作：

- 键盘：输入、建议、确认卡、返回、重试、加载更多、展开评论可完整操作；
- 语义：`tablist/tab/tabpanel`、`listbox/option`、结果 live region 与焦点移动保持一致；
- 触摸：点击目标 ≥44px，避免只在文字上绑定关键动作；
- Alook/Android：跨模块入口先验证 `<a href>` 离线可点击，JS 只增强；
- 视觉：对比度、窄屏换行、超长校名/专业名、safe-area、低高度屏幕、减少动画；
- 页面不使用会让返回、下一步或来源被遮挡的永久 sticky 层。

### TX-06：测试、证据和回归门槛

#### 静态测试

- 入口/出口合同与安全 `returnTo`；
- entity canonicalization 与 `invalid_entity`；
- history push/replace 规则；
- focus/scroll reason 规则；
- fail-closed 与无幻觉文案；
- 词表、原生 `<a>`、无动态导航死链；
- 更新旧 verifier 的版本硬编码，确保测试与当前 v159 运行时一致。

#### 浏览器旅程

1. `/ln-rank/` 分数/学校卡 → Tongxue → 返回，检查分数、筛选、滚动锚点；
2. `/ln-rank/` 专业卡 → `/major-path/` → Tongxue，检查专业代码、主题、返回；
3. 学校全部专业 → 学校体验，检查学校实体与专业范围不混淆；
4. 地区 → 城市 → 具体学校，检查中间态不会自动选错学校；
5. 专业模糊词 → 具体专业确认 → 专业体验，检查仅一专业；
6. 直接 `school+entity` 和 `scope=major`，检查自动交接阶段和无来源时的独立查询提示；
7. 结果中段加载更多/展开/重试，检查滚动和焦点不跳；
8. 分享链接、刷新、前进、后退，检查上下文边界和幂等恢复。

#### 网络/数据故障矩阵

| 故障 | 必须保留 | 禁止发生 |
|---|---|---|
| 离线/请求超时 | 输入、对象、来源返回、上次已验证结果 | 伪造评论或摘要、显示成功 |
| API 4xx/5xx | 当前页结构、可重试动作 | 把服务错误写成“没人评价” |
| HTML/非法 JSON | 当前查询口径、诊断后置 | 把错误页面当数据 |
| 空评论/来源无记录 | “暂时没有可展示”与边界说明 | 推断体验好坏或现实不存在 |
| 分页失败 | 已读评论、滚动位置 | 清空首屏、跳回顶部 |
| 旧请求晚到 | 最新查询 | 覆盖新对象或新上下文 |

## 6. 发布与回滚门槛

1. 先提交计划与状态，不把审计意见伪装成代码已完成；
2. 每个 TX 形成静态证据、浏览器证据和失败证据；
3. PR required checks 全部通过，且测试针对当前 head SHA；
4. Preview、Production 与提交 SHA 一致后，验证关键入口、返回、断网和外链；
5. 发现来源或返回合同回归时停止合并，保留上一份可验证结果并回滚到已知 SHA；
6. 合并后再次核验 main SHA、页面入口、静态资源版本、CI 与 Production；
7. 任何“没查到线上结果”的情况标记为 `unknown`，等待下一次可验证检查，不作乐观结论。

## 7. 完成定义

- 用户从学校卡、专业卡、地区、直接链接、分享或刷新进入后，都能看懂当前对象与来源；
- 返回能恢复原查询的分数、专业、筛选、结果模式和阅读位置，且不会误回首页；
- 结果内部更新不抢滚动、不丢焦点、不重复请求；
- 学校体验、专业路径、学生留言、官方事实和来源站的边界清楚；
- 离线、弱网、坏响应和空源均 fail-closed，无任何前端或模型补写；
- Android/Alook 的关键入口在脚本未就绪时仍可用；
- PC/Pad/Android 无横向溢出，键盘和触摸均可完成主路径；
- 旧版 verifier 已升级或明确标记为 legacy，不再阻塞当前版本，也不被静默跳过；
- 所有 required checks、浏览器旅程、网络故障矩阵和生产核验完成后，才允许进入实现 PR 与 main 合并流程。
