# 跨模块查询上下文与返回恢复 v001

## 目标

让 `ln-rank`、Tongxue 和专业升学地图像同一个查询过程：进入学校体验或专业路径时保留刚才的条件，返回后恢复原查询和结果位置；直接打开任一页面时仍可独立使用。

## 所有权边界

- 继续使用 `shared/decision-context/decision-context.v001.js` 作为跨页只读上下文唯一所有者。
- 使用 `shared/decision-context/return-snapshot.v001.js` 只保存当前标签页短期的锚点、滚动位置和焦点；它不保存招生事实或家庭方案。
- 继续使用现有学校实体、专业代码、Selection Pool、Tongxue 和 major-path 运行时所有者。
- 不新建第二个上下文管理器、第二个返回状态机或第二套招生事实。

## 实施步骤

1. **上下文合同**：补充结果模式、返回锚点和快照键；学校入口必须携带规范实体身份，专业入口必须携带规范代码。
2. **学校体验链**：`ln-rank` 学校卡统一通过学校资源中心进入 Tongxue，携带只读上下文和安全回链。
3. **专业路径链**：`ln-rank` 专业卡进入 major-path；major-path 的专业体验入口继续携带原上下文，不重新猜专业。
4. **返回恢复**：返回 URL 恢复筛选条件；session snapshot 恢复结果锚点和滚动位置；运行时完成挂载后只执行一次定位，用户开始滚动后停止自动定位。
5. **人类文案**：目标页面显示“来自刚才的专业初选/专业升学地图”，按钮使用“返回刚才的查询”，不暴露内部上下文术语。
6. **断网边界**：目标页接口失败时仍显示身份、当前条件和返回入口；返回页保留原输入，不能把旧结果伪装成新查询。

## 验收场景

- 分数结果 → 学校体验 → 返回，分数、筛选条件、结果区和学校实体不丢。
- 分数结果 → 专业路径 → 专业体验 → 返回，原结果和多专业确认列表不丢。
- 学校全部专业 → 学校体验 → 返回，继续停留在学校全部专业区域。
- 刷新、前进、后退、直接打开无上下文 URL、慢网和接口失败。
- PC、Pad、Android 390、Android 360；无横向溢出、无重复请求、无滚动争抢。

## 发布与恢复

运行时变更沿用当前站点发布合同，记录能力版本 `cross-module-context-handoff-v001` 和修订 `r048-cross-module-context-handoff`。每个阶段把最终 head SHA、测试结果和失败原因写入 `.codex/progress/unified-cross-module-context-handoff-v001.json`。只有最终 head 的必需检查全部通过，才允许标记 Ready 和合并 `main`；合并后重新核验 main、Pages、正式域名、资源图和关键跳转链。

## 完成条件

- 三条跨模块链均使用规范身份和统一上下文合同。
- 返回后恢复筛选条件、结果状态和阅读锚点。
- 目标页失败仍可安全返回，且不会产生虚假招生事实。
- 架构、文案、资源图、保护路径和浏览器矩阵检查全部通过。
