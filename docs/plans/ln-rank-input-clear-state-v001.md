# ln-rank 输入清空与历史恢复修复 v001

## 问题

当前专业优先、学校优先和共享工作区在读取输入框时使用了“DOM 值为空就回退 state”的写法。用户清空输入框后，空字符串会被当成输入框不存在，旧关键词因此重新进入查询条件；从 URL 返回到没有对应参数的历史状态时，输入框也不会被清空。

## 可执行改动

1. 输入框元素存在时始终以其实时 `value` 为准；只有元素尚未挂载时才读取 state 作为恢复兜底。
2. 三个入口统一采用该规则：分数结果、学校全部专业、按专业找学校。
3. 历史 URL 恢复时，无论参数是否存在，都同步清空或写入学校、专业和分数输入框。
4. 增加合同回归：禁止 active ln-rank owner 使用空值回退旧 state，并验证缺失 URL 参数会清空 DOM 输入。
5. 缓存修订推进到 `r032-input-clear-state`，专业筛选上下文推进到 `major-filter-context-v003`；全站 canonical release 仍为 `v3.9.90.2 / v3990_2`。

## 验收

- 专业优先：确认一个专业后清空追加输入，不再恢复上一次草稿。
- 学校优先：清空专业关键词后查询，不再带入旧专业条件。
- 返回/前进：URL 缺少 `school`、`majorKeyword` 或 `score` 时，页面输入框同步为空。
- 既有专业解析、学校实体确认、三入口跳转、资源合同和版本合同继续通过。
