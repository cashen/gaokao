# Tongxue 首次打开加载状态与非阻塞启动计划

## 目标

解决 Android 手机首次打开 /tongxue/ 时，在用户尚未输入任何内容前等待时间过长、容易误以为页面卡住的问题。

本次改动只改善启动反馈与启动调度，不改变学校/专业识别、模糊候选、单专业查询、来源边界或学生留言分页规则。

## 用户可见规则

1. 页面骨架、Logo、搜索框和查询对象切换先显示。
2. 学校和专业目录准备期间，搜索框下显示黄色状态：正在准备学校和专业目录，马上可以查询。
3. 目录成功后显示绿色状态：学校名单已准备好：支持 N 所普通高校及独立招生实体，或专业范围对应的目录提示。
4. 目录失败后显示红色状态：目录加载失败，请点击重新加载，同时提供“重新加载”按钮。
5. 状态位保留固定最小高度，状态切换不得造成页面跳动。
6. 状态不能只依赖颜色，必须同时有文字和可读的语义状态。

## 实施任务

### TX-01：启动状态位

- 将现有 indexStatus 改为固定高度的状态容器。
- 使用 preparing / ready / error 三种状态语义。
- 黄色、绿色、红色只作为辅助，不删除文字。
- Android 小屏保持可换行，不能横向溢出。

### TX-02：目录后台准备

- startTongxueRuntime() 不再把目录加载作为首屏阻塞点。
- 绑定输入、切换和重试事件后立即返回可见页面。
- 目录加载完成后再启用学校解析能力。
- 专业查询仍可使用既有专业解析逻辑，不被学校目录等待拖住。

### TX-03：提前输入与安全恢复

- 目录尚未完成时允许用户输入。
- 用户提前点击查询时保存最后一次输入，目录 ready 后仅在输入仍一致时自动继续。
- 目录失败不自动篡改输入、不改变候选、不写入错误的学校实体。
- 重试使用新的请求 URL，绕开失败的默认 Promise；成功后恢复正常查询。
- 带学校/专业上下文的直达链接仍必须等待目录后恢复原流程。

### TX-04：跨终端与布局

- PC、Pad、Android 共用同一状态合同。
- 不使用 MutationObserver、任意 setTimeout 或 scrollIntoView 解决布局。
- 不清空用户输入，不抢滚动位置，不新增无限加载。
- 保留学生留言分页与证据层级说明。

## 测试清单

- 静态：git diff --check、模块语法检查。
- 确定性：状态文案、状态色阶、重试按钮、固定高度、ready 后按钮状态。
- 浏览器：PC / Pad / Android 冷缓存首次打开、目录 ready、目录失败重试、ready 前提前输入。
- 回归：学校简称/地区候选、专业模糊候选、单专业查询、直达 URL、返回来源入口。
- 性能：记录首次可见、首次可操作、目录 ready、首次查询结果四个时间点；不得把 API 查询时间误算为首次打开资源时间。
- 发布：Preview 使用当前 PR head 验证；Ready 后第二轮检查通过；以 expected head 合并；合并后核对 main、Production 和 /tongxue/。

## 断网/中断续作规则

每次继续前必须依次读取：

1. docs/status/tongxue-startup-status-v001-status.json
2. .codex/progress/tongxue-startup-status-v001.json
3. GitHub main、本分支、PR、PR head SHA、相关 CI 和 Preview/Production 状态。

若提交、PR、CI 或部署结果未知，不得重复写入；先按精确 SHA 或标题查询远端状态。只从第一个未完成的 TX 任务继续，禁止依据旧会话猜测。

## 完成定义

- 首次打开期间用户能明确看到黄色准备状态。
- ready 时出现绿色状态，失败时出现红色状态并可重试。
- Android 不再出现无提示的长时间空等。
- 所有测试通过后才将 PR 合并到 main。
