# 模拟志愿 v013：专业宽容输入与校专业匹配

## 目标
让普通家长可以自然地输入专业名称或专业代码；系统负责识别、纠正轻微书写错误、给出相近专业候选，并在已有学校上下文中核对“这所学校有没有这个专业”。

## 交互契约
1. 专业输入框文案为“输入专业名称或代码”。
2. 数字输入按 2026 本科专业目录代码识别。
3. 完整专业名称直接识别并转换为规范代码 + 中文名。
4. 不完整名称、常见叫法和轻微错别字通过现有共享 resolver 给出候选；高置信度只提示“可能是这个专业”，不擅自替用户确认。
5. 候选操作在卡片内展开的小型浮层中完成，选中后自动收起。
6. 学校已填写且专业已识别后，通过现有 `/api/ai/major-history` 的 `major + schoolKeyword` 查询核对该校是否存在对应招生记录。
7. 找到记录：显示“已找到该校相关招生记录”，并复用返回的历史分数/位次，不复制或编造招生事实。
8. 没找到记录：显示明确的“这所学校暂未找到这个专业”核对提示，但不删除用户输入。
9. 查询失败：不把网络故障误判成“不匹配”，只提示“暂时无法在线核对”。
10. 输入过程中允许保存草稿，用户不需要一次输入完。

## 数据边界
- 专业身份唯一归属 `shared/resources/majors/major-catalog-contract.js` + 2026 本科专业目录。
- 专业历史与学校匹配复用 `/api/ai/major-history`；不在前端复制历史招生事实。
- 统一 catalog resolver 已包含精确、别名、包含和 Levenshtein 模糊匹配能力；v013 只做 UI 编排和结果解释。
- 低置信度不自动纠正；由用户选择。

## 实现步骤
### Step 1：输入层
- 保持现有 `majorCode` 数据字段兼容。
- placeholder 从“专业代码，例如 080301”改为“输入专业名称或代码”。
- 输入时保留草稿文本，清除过期的专业名称/历史结果。

### Step 2：候选层
- 接入共享 `createMajorCatalogResolver().findByCode/findByName/search`。
- 输出最多 5 个候选。
- 高置信度显示单个建议；否则显示“找到几个相近专业”。
- 支持鼠标、键盘、Android 触控。

### Step 3：学校上下文验证
- 专业标准化后调用 `/api/ai/major-history`。
- 结果按学校名称规范化后优先精确匹配。
- 有匹配记录时回填三年历史；无记录时进入 `majorMatch=mismatch` 状态。
- 网络/接口异常进入 `majorMatch=needs-check`，不做错误否定。

### Step 4：可见反馈
- 在专业字段下增加一行轻量辅助文案。
- 状态只承担“识别/核对”角色，不改变家庭决策按钮。
- 保持 v010 三年历史紧凑信息带和 v012 家庭决策区。

### Step 5：回归测试
- 数字代码：080301 → 测控技术与仪器。
- 完整中文：测控技术与仪器 → 080301。
- 部分中文：计算机 → 多个候选。
- 错别字：测空技术与仪器 → 给出测控技术与仪器建议。
- 校专业匹配：辽宁科技大学 + 测控技术与仪器 → 命中。
- 校专业不匹配：辽宁科技大学 + 不存在/其他专业 → 明确提醒。
- API 失败：保留输入，不误报专业不存在。
- 1280px / 390px 均验证；候选按钮触控目标不少于 42px。
- 现有 v007/v010/v012 回归不受影响。
