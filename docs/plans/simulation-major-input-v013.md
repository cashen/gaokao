# 模拟志愿 v013：专业宽容输入与校专业匹配

## 用户问题
普通家长不一定记得六位专业代码，也不一定能准确写出正式专业名。页面不能把输入错误当成用户错误，更不能强迫用户学习数据库字段。

## 产品原则
- 能输入什么就尽量理解什么：中文、代码、简称、少量书写错误均进入理解流程。
- 系统帮助确认，不替家长拍板：模糊匹配只给候选，不静默改成另一个专业。
- 学校是上下文：专业全国存在，不代表当前学校有该专业；两层事实必须分开表达。
- 找不到 ≠ 一定不存在：接口故障、历史数据缺失、当年未招生都不能统一写成“没有这个专业”。
- 不重复建设数据：专业身份复用共享 2026 本科目录 resolver；历史招生事实复用既有 `/api/ai/major-history`。

## 交互流程
1. 输入框提示“输入专业名称或代码”。
2. 精确代码/名称立即识别。
3. 不完整名称、别名、错别字显示最多 5 个候选。
4. 用户点击候选后才正式确认专业；高置信度也不自动替用户选择。
5. 已填写学校时，自动用“学校 + 标准专业名”检查招生历史。
6. 命中：显示“✓ 已找到该校相关招生记录”，并复用返回的历史分数/位次。
7. 未命中：显示“⚠ 这所学校暂未找到该专业，请核对学校或专业”，保留用户输入。
8. 网络/接口故障：显示“暂时无法在线核对”，绝不误判为“不存在”。
9. 输入过程中允许保存草稿，用户不需要一次输入完。

## 数据边界
- 专业身份唯一归属 `shared/resources/majors/major-catalog-contract.js` + 2026 本科专业目录。
- 专业历史与学校匹配复用 `/api/ai/major-history`；不在前端复制历史招生事实。
- 统一 catalog resolver 已包含精确、别名、包含和 Levenshtein 模糊匹配能力；v013 只做 UI 编排和结果解释。
- 低置信度不自动纠正；由用户选择。

## 实现步骤
### Step 1：输入层
- 保持现有 `majorCode` 数据字段兼容。
- placeholder 从“专业代码，例如 080301”改为“输入专业名称或代码”。
- 输入时保留草稿文本，清除过期的专业名称/历史结果。

### Step 2：候选层
- 接入共享 `createMajorCatalogResolver().findByCode/findByName/search`。
- 输出最多 5 个候选。
- 支持鼠标、键盘、Android 触控。
- 不做静默模糊替换，避免把“计算机”等宽泛输入误选成单一专业。

### Step 3：学校上下文验证
- 专业标准化后调用 `/api/ai/major-history`。
- 结果按学校名称规范化后优先精确匹配。
- 有匹配记录时回填三年历史；无记录时进入 `majorMatch=mismatch` 状态。
- 网络/接口异常进入 `majorMatch=needs-check`，不做错误否定。

### Step 4：可见反馈
- 在专业字段下增加一行轻量辅助文案。
- 用候选浮层承载选择，不把卡片撑高。
- 状态只承担“识别/核对”角色，不改变 v012 家庭决策按钮。
- 保持 v010 三年历史紧凑信息带。

### Step 5：回归测试
- 数字代码：080301 → 测控技术与仪器。
- 完整中文：测控技术与仪器 → 080301。
- 部分中文：计算机 → 多个候选且不自动选择。
- 错别字：测空技术与仪器 → 给出测控技术与仪器建议，由用户点击确认。
- 校专业匹配：辽宁科技大学 + 测控技术与仪器 → 命中并保留三年历史。
- 校专业不匹配：辽宁科技大学 + 临床医学等全国目录专业 → 明确核对提醒。
- API 失败：保留输入，不误报专业不存在。
- 1280px / 390px 均验证；候选按钮触控高度不少于 42px。
- v007 移动布局、v010 三年历史、v012 家庭决策均回归。
