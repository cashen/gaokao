# 模块根导航与跨模块返回 v001

## 背景

线上核验发现，同学你好页面虽然有全站壳层，但仍加载旧版 shell，只提供单向“返回专业初选”；共享全站导航也没有“同学你好”模块入口。家长在 PC、Pad、Android 上从一个模块进入另一个模块时，无法同时得到清楚的模块根入口和“回到刚才过来的路径”语义。

本任务只处理导航层，不改变 Tongxue 查询、目录加载、资源缓存身份、分数/位次、学校/专业语义、历史数据或 fail-closed 规则。

## 设计结论

1. 全站核心模块根入口保持稳定、短而可理解：家庭首页、专业初选、同学你好。
2. 桌面端把“同学你好”补进既有全站导航；不把模块入口写成另一个模块的子功能。
3. Pad 保留核心模块入口可见，避免既有辅助入口挤掉模块入口。
4. Android 提供可横向阅读的“模块切换”条，触控目标保持可操作；全站导航不因屏幕窄而完全消失。
5. 跨模块进入时显示“返回刚才的模块”，目标保存刚才的完整同源路径（query/hash 一并保留）；直达页面没有真实历史时隐藏返回，不伪造历史。
6. 同模块内部路径不覆盖跨模块返回点；浏览器原生后退仍保持原有语义。
7. Tongxue 顶部旧的单向返回链接改由同一导航层接管；没有历史时不显示误导性的“返回刚才”。

## 子任务

- **MN-01：远端基线与范围确认**
  - 核对最新 main、开放 PR、CI/Preview/生产状态、Tongxue status 和相关 plan。
  - 实测 Tongxue 与专业初选在 PC；检查共享 shell、Tongxue 旧 shell 和现有返回路径。
  - 将独立 major-bands 503/zero-job 记录与本任务隔离。
- **MN-02：实现模块根导航**
  - 新增独立、可缓存识别的导航 JS/CSS。
  - 为使用共享壳层的主页面及专业升学地图接入。
  - 在共享全站导航中补充 Tongxue 根入口，并提供移动端核心入口。
- **MN-03：实现跨模块返回**
  - 使用 sessionStorage 保存同源、同模块边界内的最近跨模块路径。
  - 仅在存在真实上一模块路径时展示返回；严格拒绝外域、协议相对路径和非法值。
  - 保留分数、筛选、scope、query/hash，不介入业务查询状态。
- **MN-04：静态与脚本验证**
  - 验证 JS 语法、模块映射、导航顺序、返回目标清洗、移动端合同和旧链接接管。
  - 验证不触碰 Tongxue v159-startup001 固定资源身份。
- **MN-05：PR/Preview/多终端验证**
  - exact base/head 核对；PR Ready 前后重新核对 head。
  - 运行静态合同、单元/脚本、CI、Preview。
  - 核验 PC、Pad、Android：模块根入口、当前态、跨模块返回、完整路径保留、无横向溢出。
- **MN-06：合并后生产收尾**
  - 仅合并所有相关检查通过的 exact head。
  - 合并后重新核对 main SHA、Cloudflare Pages、生产部署、正式地址和 Tongxue 固定资源身份。
  - 每个子任务完成后更新 status；不得把未知/超时当成功。
