# ln-rank major-all 多专业可见化交互 v002

## 背景

v001 已实现单专业、多专业并集、模糊候选确认、分数/地区/项目条件和三年趋势；但当前 PC/Pad/Android 把“多个专业”隐藏在一个输入框的标点语法中，首次使用者容易不知道如何添加第二个专业。

## 目标

让家长不需要记忆 `/`、顿号或逗号语法，也能完成：

1. 输入一个专业方向；
2. 选择规范本科专业；
3. 点击“再添加一个专业”；
4. 再次输入并确认；
5. 看到“已添加专业”；
6. 点击“统一查询”。

保留一次输入“机械/测控/材料”的快捷方式，但不再把它作为唯一入口。

## 交互合同

- 输入框标签改为“添加想了解的专业”，旁边明确提示“可添加多个”。
- 首个专业候选确认后，出现明确的“＋再添加一个专业”动作。
- 已确认专业用可读的标签/卡片展示：专业名、代码、移除。
- 添加动作只更新 draft，不发请求、不覆盖已提交结果。
- 未确认的专业不能加入查询；查询按钮显示“还差 1 个专业待确认”。
- 查询提交后显示“已查询 N 个专业”，结果仍按学校×专业×项目独立记录，不做一期横向对比。
- 保留多专业快捷输入和自动拆分，支持“机械/测控/材料”“机械、测控、材料”“机械和测控”。
- 点击“再添加一个专业”后，输入框清空并获得焦点；输入法弹起时不遮挡候选与主按钮。

## 多终端

- PC：候选与“再添加”动作在输入区内连续可见，已确认专业横向排列，过宽换行。
- Pad：单列布局，添加动作与查询按钮全宽，候选按钮不挤压。
- Android：不使用遮挡内容的固定大底栏；触控目标至少 44px；输入框聚焦后候选和已选专业顺序稳定。
- 所有终端共享同一 resolver、draft、query 和结果状态，不复制业务逻辑。

## 测试门槛

- 单专业：输入、确认、查询。
- 多专业显式流程：确认机械 → 再添加 → 确认测控 → 查询。
- 快捷输入：机械/测控/材料。
- 移除后继续添加、清空后回到初始态。
- 候选未确认时禁止查询。
- PC/Pad/Android/compact Android 不横向溢出，不丢失焦点，不出现重复查询。
- score-bands、school-all、selection pool、major-path、student voice 保持回归。
