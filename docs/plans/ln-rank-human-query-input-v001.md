# ln-rank 三类输入人类查询协议 v001

## 目标

把 ln-rank 中“专业、分数、学校”的输入体验统一到同一条符合家长直觉的查询流程：

> 先输入 → 看懂系统如何理解 → 必要时确认 → 才提交查询 → 结果继续沿用现有工作区和事实数据。

统一的是交互协议、确认时机、失败关闭和上下文继承；不把三类业务错误地做成一个解析器：

- 专业：继续由现有专业候选解析器负责方向、专业实体、专业大类和模糊词确认。
- 分数：由确定性数值解析负责单点、范围、上下界，并明确区分“分数”和“位次”。
- 学校：继续使用现有规范学校/别名/校区解析器，先确认实体，再进入学校查询。
- 模型只能提出解释建议，不能补写不存在的学校、专业、分数、位次或历史数据。

## 技术流与子任务

### HQI-01 远端接管与所有权核验（已完成）

- 从最新 main 精确创建本分支。
- 重新核对 main SHA、未关闭 PR、Checks、Cloudflare Pages、生产地址、已有 status 与 release contract。
- 确认现有工作区、学校目录、专业候选解析器仍是唯一业务真相所有者。
- 证据写入 status 文件，未知状态不作成功推断。

### HQI-02 版本与契约接入

- 在 shared/resources/release/current-release.js 增加本功能的规范版本身份：lnRankHumanQueryInputVersion: ln-rank-human-query-input-v001。
- 在活动运行时契约/资源图中登记该入口与版本，保证版本不是散落在单一模块的孤立字符串。
- 运行时代码从规范 release contract 读取版本；公开文案不暴露内部版本号。
- 每次后续修订都必须递增规范版本或对应功能版本，并同步所有受影响的契约、入口、manifest、校验器和 status；禁止只改显示字符串。
- 如果仓库的统一发布校验判定需要整体 generation 变更，必须一次性同步整个活动资源图；不得制造混合 generation。

### HQI-03 共享的确定性解释协议

- 新增一个纯函数、可单测的输入解释模块；它只负责 typed proposal/状态投影，不创建第二套工作区状态机。
- 统一返回原始输入、归一化文本、领域类型、解释状态、是否需要确认、用户可读说明。
- 分数至少覆盖：空值、单点、带“分”、合法范围、下界、上界、非法数值、超出支持范围、明显的位次表达。
- 分数范围/上下界不能静默塞进当前只接受单点的历史查询 API；若后端尚不支持该语义，必须明确提示用户改用单点参考分数。
- 学校和专业的解析由现有 owner 注入/调用，不复制目录或候选算法。
- fail-closed：未确认的实体、不明确城市/学校、不能证明的数据，不能成为已提交筛选条件。

### HQI-04 分数接入

- 把分数输入从“数字字符串直接写入 state”改为“草稿 → 解释 → 确认/纠错 → commit”。
- 保留现有 score-bands、school-all、major-all 的业务查询语义与 API 参数。
- 580、580分等确定单点可直接显示“按 580 分查询”；570-590、600以上等暂不能映射到单点 API 的表达必须停止提交并说明原因。
- 位次23000 不得被解析成 23000 分；必须提示当前字段是分数，并保留输入让用户修正。
- 保留用户已确认的分数上下文，切换专业/学校任务时不得无故清空。

### HQI-05 学校接入

- 在提交 API 前调用现有规范学校解析器做预检。
- 精确学校/稳定别名解析成功后显示规范名称和必要的校区/实体信息。
- 城市、学校片段、多候选、未知学校先给出确认选择；未确认时不提交原始字符串作为事实条件。
- 选择候选后回填同一工作区的学校实体，不另建学校状态机。
- 支持“沈航”“沈阳航空航天大学”等常见人类输入，同时明确“沈阳”是地区还是学校必须由用户确认。
- “介绍一下沈航”这类研究/说明意图不得静默改成筛选条件。

### HQI-06 统一提交与上下文继承

- 保留现有 selection-workspace-orchestrator 为唯一提交和持久化 owner。
- 三类输入统一遵循 draft → interpretation → confirmation → commit → submit。
- 例：580分，只看电气能分别确认分数与专业；沈航，看所有专业能确认学校后进入学校根任务；上一轮的学校，改看计算机继承可证明上下文。
- 确认失败、网络失败、目录未准备好时保持上一次已提交状态，不把半成品写入正式筛选。
- 不新增 MutationObserver、滚动 owner、并行查询状态机或模型事实层。

### HQI-07 人类 UI 文案与多终端

- PC、Pad、Android 均使用同一业务分支；只允许布局适配，不允许设备专属业务语义。
- 在输入附近提供紧凑的“我理解为……”确认区，避免把技术状态堆在顶部。
- 语气面向家长：说明系统将按什么查、为什么需要确认、下一步怎么改。
- 处理键盘弹出、窄屏换行、候选按钮触控尺寸、焦点回收和返回上一任务。
- 公共文案通过 node tools/audit-human-copy-v001.mjs；不向用户展示内部版本、resolver、entityId 等术语。

### HQI-08 验证

静态合同、单元/脚本、CI、Preview 必须全部通过，且不得虚构结果：

- 静态检查：入口、release contract、资源图、固定 Tongxue 资源身份、无旧 v=159-major001。
- 单元/脚本：单点分、分数范围/上下界、位次防误判、学校精确/别名/歧义/城市、专业候选确认、fail-closed、上下文继承。
- CI/Checks：精确 head SHA 上所有相关检查通过。
- Preview：使用本 PR 的 Cloudflare branch/commit Preview；验证 PC、Pad、Android 宽度与真实键盘交互。
- 生产：合并后重新核对 main SHA、Cloudflare Production、正式地址和入口资源身份。
- 记录真实 URL、SHA、检查结论和任何网络中断；网络中断期间状态为 unknown，不重复写入。

### HQI-09 Ready、合并与收尾

- Ready 前重新获取 PR base/head SHA、draft/ready/merged 状态与所有 Checks。
- Ready 后再次获取精确 head SHA 和所有 Checks；任何 pending/failure/unknown 都不能合并。
- 使用 expected_head_sha 合并，避免误合并移动后的 head。
- 合并后更新 status 文件并验证 main SHA、Cloudflare Production、正式地址和核心查询语义。
- 最终 status 必须列出完成子任务、证据、版本身份、已知独立问题和固定 Tongxue 资源。

## 人类验收样例

| 输入 | 期望 |
| --- | --- |
| 580 / 580分 | 解释为单点分数 580，允许进入现有查询 |
| 570-590分 | 显示范围含义；当前单点 API 不支持时停止提交并说明 |
| 600以上 | 显示下界含义；不伪装成 600 单点 |
| 位次23000 | 明确提示这是位次，不写入分数 |
| 沈航 | 使用现有学校解析器；若有唯一实体则确认规范名称，否则列候选 |
| 沈阳航空航天大学 | 确认规范学校实体后再查询 |
| 沈阳 | 不擅自当学校或地区，要求选择 |
| 电气 / 机械 | 沿用现有专业候选确认；不静默替换专业 |
| 580分，只看电气 | 分数与专业分别解释，均确认后提交 |
| 介绍一下沈航 | 走说明/研究意图，不修改筛选条件 |
| 网络中断/目录未完成 | 保留已提交条件，停止本次提交并给出可恢复提示 |

## 明确不在本 PR

- major-bands 算法、并发、503、bounded-fanout job 编排。
- Tongxue 资源身份或首次打开黄色/绿色状态。
- 招生事实、历史分、位次、学校和专业数据生成。
- 重新启用已退役的 intent-interpreter.js。
- 复制学校目录、专业候选解析器或建立第二个事实源。
- 以模型输出覆盖确定性事实。
- 为了版本号单独修改无关页面或制造孤立 asset generation。

## 断网恢复规则

1. 每个新动作前重新读取：最新 main SHA、分支 head、所有未关闭 PR、PR base/head/draft/ready/merged、精确 head Checks、Cloudflare Preview/Production、当前 task status 和 plan。
2. 若上一次写入结果未知，不重复写入；先用远端 ref、文件 blob SHA、PR 状态或 commit 查询确认是否已成功。
3. 恢复后从 status 文件中第一个未完成子任务继续；已完成子任务不重做，不凭记忆假设测试或部署成功。
4. 任何代码/契约/文案修订都要同步版本号、受影响资源图/入口、status 证据和 PR plan 勾选状态。
5. 只有在精确 head SHA 上所有相关 CI、静态检查、单测和 Preview 均为成功时才 Ready/合并。
6. 合并必须带 expected_head_sha；合并后重新确认 main SHA 与生产。
7. Cloudflare 或浏览器无法访问时记录为 unknown；不得把旧 Preview、旧 main 或截图推断为本次 head 的结果。
