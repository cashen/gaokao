# /tongxue 学校与单专业体验入口统一计划 v001

## 1. 目标与边界

当前 `/tongxue` 已经支持学校体验和专业学生留言，但首页标题、输入提示、快捷示例和状态文案主要只说明“查学校”，导致专业能力不可发现。本计划修正入口表达，并把专业输入统一接入全站最新专业意图解析合同。

`/tongxue` 的专业模式只负责：

- 通过精确名称、代码、简称或模糊表达找到一个本科专业；
- 在模糊或层级表达下展示候选并要求确认一个具体专业；
- 展示该专业的专业资料、升学路径和学生公开留言；
- 保留来源、证据数量和“不能由少量留言外推整体”的边界。

`/tongxue` 不负责：

- 多专业组合或多专业结果合并；
- 专业类/招生大类批量查询；
- 分数、位次、三年趋势或志愿位置判断；
- 把专业方向自动展开为多个专业后请求学生留言接口。

这些能力继续由 `/ln-rank` 的专业查询和分数历史模块负责。

## 2. 当前代码审计结论

当前代码已有 `scope=school|major`、专业候选确认、专业来源接口和专业资料展示，但存在四个问题：

1. `/tongxue/index.html` 默认标题是“找学校，看看大家怎么说”，输入框只写“输入学校、简称或地区”，快捷示例也只有学校/地区；
2. `applyScopePresentation` 能切换专业文案，但没有把 scope 开关作为首页的显式入口；
3. `/tongxue` 专业解析主要使用旧的 `major-catalog-contract` 适配逻辑，和 `shared/resources/majors/major-intent-resolver.v001.js` 的全专业意图层级尚未完全统一；
4. 专业模式部分状态仍可能显示学校名单、学校错误或学校范围提示，造成文案与实际 scope 不一致。

## 3. 产品方案

### 3.1 唯一 scope 开关

复用已有 `scope=school|major` 状态合同，在搜索入口增加一个轻量的二段式开关：

```text
[看学校体验] [看专业体验]
```

不跨页面复制 `/ln-rank` 的 DOM，也不创建另一套状态机；由共享 scope 语义驱动 `/tongxue` 的本地表现、URL 和 API 参数。

### 3.2 学校模式

```text
找学校，看看大家怎么说
输入学校、简称或地区
```

保留学校、地区、校区实体解析和现有学校查询行为。

### 3.3 专业模式

```text
找专业，看看大家怎么说
输入专业名称、简称或代码
支持模糊查找，但每次先确认一个具体专业。
```

专业按钮显示“看专业怎么说”，准备状态显示专业目录已准备好，错误状态也使用专业语义。

### 3.4 单专业确认规则

| 输入 | 行为 |
|---|---|
| 完整专业名称 | 直接确认并查询一个专业 |
| 专业代码 | 直接确认并查询一个专业 |
| 电气、机械、计算机 | 展示候选，选择一个具体专业 |
| 机、工科、医学 | 只展示继续选择提示，不请求接口 |
| 计算机类、机械类 | 说明专业类不等于具体专业，要求选择 |
| 一级学科机械工程 | 说明学科口径边界，要求选择本科专业 |
| 机械/电气、机械、电气 | fail-closed，提示一次查看一个专业 |

确认后接口只能收到一组标准身份：

```text
scope=major
majorCode=一个专业代码
major=一个标准专业名
```

## 4. 技术方案

### TX-00：计划与断点

- 本计划写入 PR；
- 建立 `docs/status/tongxue-major-single-scope-v001-status.json`；
- 每次恢复先读取 PR、状态文件、main SHA、head SHA、CI 和部署状态；
- 不把未验证的推断写成已完成。

### TX-01：入口文案与 scope UI

- 修改首页标题、描述、输入提示、快捷示例、按钮和页面 title；
- 将 scope 开关放在搜索区可见位置；
- 学校/专业切换时同步 placeholder、aria-label、状态提示和 reset 行为；
- 保持 PC、Pad、Android 共用状态，不保留两套查询表单。

### TX-02：统一专业意图适配

- `major-intent-resolver.v001` 作为专业目录和语义层级唯一 owner；
- `/tongxue` 只增加薄适配层，将解析结果投影为单专业候选；
- exact、code、alias、direction、major-class、discipline、broad-field、unknown 均保留边界；
- 模糊输入不得静默替换成一个专业。

### TX-03：单专业查询链路

- 候选选择后才进入 `scope=major` 查询；
- 保留 `majorCode` 和标准 `major`；
- 专业资料、学生留言、升学路径分层渲染；
- 专业来源失败时 fail-closed，不补写学生体验。

### TX-04：多专业与过宽词防护

- 识别 `/`、顿号、逗号、和/与/及等多专业输入；
- 不建立多专业池，不合并候选，不发批量 API；
- 过宽词只进入候选/说明状态；
- school scope 的学校名不能被专业词误抢，保留现有学校优先判定。

### TX-05：文案与状态完整性

- 修复专业模式中的学校名单、学校错误、学校空结果文案；
- 更新 loading、not found、ambiguous、source unavailable 等状态；
- 更新页面 title、顶栏、切换按钮和可访问性标签；
- 来源信息仍放在合适的 footer/技术信息层，不复制大量来源正文。

### TX-06：测试

- 883 专业、92 专业类、13 学科门类覆盖；
- exact/code/alias/fuzzy/direction/broad/discipline 测试；
- 多专业不请求测试；
- school/major scope 参数和单一专业 API 测试；
- 学校、地区、独立校区原有回归；
- PC、Pad、Android 浏览器测试；
- Preview/Production 当前 head SHA 测试。

### TX-07：发布与合并

- Draft PR 全部 required checks 通过；
- Preview 和 Production 使用当前 head SHA 核验；
- Ready 后重新等待第二轮检查全绿；
- 使用 expected head SHA 合并；
- 合并后核验 main SHA、部署 SHA 和学校/专业真实入口。

## 5. 验收矩阵

```text
默认首页准确说明学校和专业两种能力
学校/专业开关可见、可键盘操作、触控可用
电气工程及其自动化 / 080601 直接进入单专业
电气 / 机械 / 计算机 进入候选确认
机 / 工科 / 医学 不直接查询
计算机类 / 一级学科机械工程 不冒充具体专业
机械/电气 不产生多专业请求
专业 API 只有一个 majorCode 和一个 major
专业文案不出现学校名单/学校错误语义错位
学校原有地区和校区实体行为不回归
PC、Pad、Android 无横向溢出、丢输入、旧结果污染
```

## 6. 合并门槛

只有在计划全部完成、静态和浏览器测试通过、最终 head 的所有 required checks 绿色、Preview/Production 与当前 head SHA 一致，并完成合并后 main 核验时，才允许合并。
