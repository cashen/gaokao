# 模拟志愿工作台 v016：Human Input 完整收口

- 版本：`simulation-workspace-v016.0`
- 修订：`r090-human-input-integration`
- 基线：`main / 7873c939e3cfebc4bf3e48a230de09dadd930d60`
- 页面：`/ln-rank/simulation-report.html`

## 目标

这次不再继续给 v014 叠输入补丁，而是把你已经反馈的真实问题收口到同一个工作台主路径：输入不卡顿、学校和专业严格关联、宽泛专业有反馈、错别字不擅自修改、异步请求不抢输入、换学校不残留旧确认，同时保住已有家庭状态、排序、历史数据与 PDF 能力。

## 1. 输入主路径

学校和专业输入均由 v015 Human Input runtime 接管。v006 input bridge 与 v014 input controller 不再加载；v007 保留排序、删除、家庭决策同步、PDF 兼容职责。

验收：输入、删除、切换焦点不等待网络；连续输入不会被整卡片重绘打断；旧异步结果不能覆盖当前字段。

## 2. 学校

输入学校只做候选/识别，不静默替用户选择。清空学校立即清理学校依赖的专业确认；学校变化后保留用户正在编辑的专业文字，但重新核对其实际专业关系。

验收：`辽宁 → 立即删除` 无陈旧候选；多候选时用户必须点击确认；网络失败不能伪装成学校不存在。

## 3. 专业 Human Input

支持完整名称、代码与中间态代码：`0 → 08 → 080 → 0803 → 08030 → 080301`；支持关键词和模糊输入；本地目录反馈即时出现，但不把目录候选当学校事实。

验收：`机`、`机械`、`计算机`、`自动化`、`网络` 均有相关反馈；完整专业可以精确确认；逐级 Backspace 每一步都可编辑；错别字必须由用户点击确认。

## 4. School × Major 严格交集

实际流程：专业意图 → 专业目录候选 → 已确认学校实际专业记录 → 交集 → 精确确认。

最终确认采用双键规则：实际记录如果同时有专业名称和专业代码，则两者必须同时与候选一致；不能因为同名而误确认另一专业代码。全国专业目录只用于理解意图，不得冒充学校招生事实。

## 5. 请求与性能

异步查询使用 180ms debounce、AbortController、token/snapshot、缓存。快速输入不会形成 API 风暴；输入清空/换学校会取消旧任务。网络失败单独提示，不转成“没有该专业”。

## 6. 状态边界

输入状态、学校实体、专业实体、事实状态、家庭处理状态、展开状态分离。排序/删除使用稳定 row id。重新渲染不能覆盖家庭处理、历史数据或人工核对内容。

## 7. URL 入站

保留现有从 `/ln-rank/` 或学校/专业页面带入模拟清单的能力，但补上冲突检查：`majorCode` 与 `majorName` 同时存在且指向不同专业时，直接提示“代码与名称不一致，请先核对”，禁止静默选一个。重复项目仍提示已存在。

## 8. PDF / 历史 / 家庭

不重造 PDF、历史记录与家庭决策数据源。v005/v010/v012 原有能力继续保留。验收重点是新输入运行时不能覆盖其 storage/controller 状态；生成 PDF 时必须继续读取当前用户实际清单。

## 9. 多端回归矩阵

同一组场景覆盖 390px Android、768px Pad、1280px Windows/desktop。

核心场景：快速输入、IME composition、paste、Backspace、学校变更、学校无专业、网络失败、刷新恢复、请求数量。

终端级人工检查必须重点复核 Android Chrome、Android Alook、Pad 竖横屏、Windows Chrome。自动化通过不等于 Alook 已通过。

## 10. CI 与合并

v016 专用 contract/browser workflow 只验证自身资源；完成实现后才进入 Ready。最终 Preview 必须精确对应最终 HEAD。合并必须使用 expected head SHA；合并后重新验证 main、Cloudflare Preview/Production、自定义域名、API health 与关键数据 SHA parity。
