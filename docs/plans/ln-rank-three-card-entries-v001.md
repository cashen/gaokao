# 分数/学校结果卡片三入口修复计划（v001）

## 诊断结论

GitHub main 已有三条独立入口及各自 owner：专业升学路径、跨学校专业体验、学校公开体验。回归来自 PC 专用 CSS：它把 `.student-voice-entry` 与 `.tongxue-card-entry` 强制设为 `display:none`，所以截图只剩专业路径。线上当前部署在加载结果后能看到三类 DOM，但资源版本仍与 main 不完全同源；本次增加可验证的资源缓存标识。

## 产品契约

1. 分数查询和学校查询的具体专业卡片保留三条平行入口，不合并、不重复挂载：
   - 专业升学路径：了解本科专业与相邻专业、读研方向。
   - 大学生说专业：查看跨学校学生的专业体验；不代表当前学校。
   - 大学生说学校：查看具体学校/校区的公开体验；不代表官方结论。
2. 文案区分“专业能走向哪里”“专业体验如何”“学校体验如何”，不把学生体验写成录取判断或官方结论。
3. PC 仅做紧凑化，移动端沿用现有可读布局；不改分数分组、排序、数据 owner、并发或 fenxi。

## 实现范围

- 移除 PC 隐藏两条入口的回归规则。
- 统一三条入口在 PC 卡片中的紧凑高度、间距和字号，降低卡片纵向膨胀。
- 更新三条入口标签与辅助文案。
- 在 CSS/入口资源引用上追加本次 revision 缓存标识，避免旧资源遮蔽修复。
- canonical release revision 从 r023 升至 r024。

## 验证与合并门槛

- 静态 owner/copy/cache audit：三条 class 各自唯一 owner，PC 不含隐藏规则，release r024，资源 URL 含 r024。
- browser：PC 1363px、Pad 820px、Android 390px 的分数结果和学校结果；具体专业卡片三入口存在、可见、标签正确，宽度/高度不异常，专业路径、专业体验、学校体验目标互不串线。
- 预览必须是本 PR exact head SHA；CI 通过后才转 ready 并合并 main。
- 合并后重新核对 main SHA、线上资源版本和三入口计算样式。
