# 模拟志愿工作台 v014：学校约束下的专业模糊筛选与严谨匹配

## 目标
把“学校 + 专业”的自然输入变成一个**有边界的候选筛选器**：允许简称、别名、模糊词、轻微错字，但最终候选必须回到该校真实招生记录核对。全国专业目录只能用于提出“专业名称候选”，不能证明某校开设该专业。

## 核心交互合同
1. 学校先解析到官方学校实体。官方全名/已知别名可直接识别；模糊学校只展示候选，不擅自选定。
2. 专业代码或完整规范专业名可直接识别，但随后仍必须用“已确认学校 + 实际招生记录”做最终校验。
3. “机械 / 网络 / 计算机 / 电气”等短词、方向词、宽泛词一律不自动映射到某一个专业。
4. 宽泛专业且学校已确认时，调用现有 `/api/ai/major-history?major=...&schoolKeyword=...`，只展示返回的该校实际相关招生记录；候选不存在时明确告诉用户“未找到实际招生记录”。
5. 轻微错字（如“测空技术与仪器”）只能给出目录层面的相近专业提示，用户点击确认后才进入学校实际记录核对。
6. 选择具体专业后，按学校实体 + 专业代码/规范名做严格匹配；命中才进入“已找到该校实际招生记录”。
7. 网络失败与“不存在该校专业”严格区分，失败时不得写成“没有”。
8. 不输出“可以填”“稳/保”等录取结论。

## 不幻觉边界
- 学校实体来自 `tongxue/data/school-name-resolver-v150.js`。
- 专业名称/代码候选来自共享 2026 专业目录 resolver。
- 学校-专业事实来自既有 `/api/ai/major-history` 实际投档索引。
- 如果在线实际记录不可用，只能显示“暂时无法核对”，不能把目录候选冒充招生事实。

## 必测场景
- 任意学校简称/别名 → 官方学校候选或直接识别。
- “辽宁科技大学 + 机械” → 多个实际相关专业候选，不自动变成“机械工程”。
- “辽宁科技大学 + 网络” → 多个实际相关专业候选，不自动变成“网络工程”。
- “辽宁科技大学 + 计算机” → 仅该校实际返回的相关记录。
- 任意学校 + 完整专业名/代码 → 先识别，再严格匹配实际记录。
- 任意学校 + 轻微错字 → 给出相近名称，必须点击确认。
- 不存在学校-专业组合 → 保留用户输入并显示未找到实际招生记录。
- API 失败 → 显示暂时无法核对，不判定不存在。
- 390px / 1280px：候选按钮 >= 42px，候选列表不遮挡主要输入。
