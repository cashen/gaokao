# V2.92RC2｜启动顺序、监听去重与第6步布局定版

基线：V2.92RC1。  
范围：fenxi-only update。  
边界：不改 compute-pipeline / filter-engine / plan-engine 核心公式；不改地域 hard、兴趣真实命中、原始投档数据、一分一段数据；不改变推荐结果口径。

## 本版解决的问题

1. **启动顺序错位**  
   RC1 中 `app.v2981.js` 在后续补丁尚未加载完时就可能启动。若浏览器已有 session，首轮 `autoRefresh` 可能早于 `detail-lazy / final-decision / export-md / stability-clean / interact-dedupe` 生效，导致第一轮渲染仍走重详情或旧监听。

2. **输入分数后的重复计算**  
   历史监听层较多：app 自身 input/change、filter-engine chip、interact-dedupe capture listener、refresh-scheduler 会叠加。RC2 将 interact-dedupe 的执行路径改为统一进入 refresh-scheduler，不再绕过 `ensureDataForCurrentRank` 直接 `applyFilters`。

3. **导出按钮导致第 6 步错位**  
   Markdown 自选池按钮只允许插入右侧 `.rightPanel`，不再把按钮作为 `#candidateArea` 的 grid 子项。

4. **MutationObserver 反复触发**  
   `export-md` 改为事件驱动，只监听 `ln:cards-rendered / ln:abc-rendered / ln:candidates-rendered`，不再观察 `document.body`，也不观察 `#candidateArea` 子树。

5. **第 6 步布局定版**  
   新增更强的 grid 收口：左侧详细候选 `minmax(0,1fr)`，右侧自选栏 `280px–340px`，移动端自动单列。
