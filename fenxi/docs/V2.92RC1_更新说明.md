# V2.92RC1｜加载性能与第6步布局收口版

## 本版目标
针对 V2.92RC 线上反馈的三个问题一次收口：

1. 输入分数后专业学科/详细卡片加载慢。
2. 第 6 步“详细候选与自选”区域错位。
3. 详细候选区仍可能被导出按钮或步骤伪标签挤压布局。

## 核心修复

### 1. 启动不再阻塞大模型
启动阶段只等待计算必需的专业学科核心：

- `major_taxonomy.json`
- `raw_major_alias.json`
- `subject_groups.json`
- 易混专业轻量 recordIndex

不再在用户输入分数前阻塞等待：

- `admission_major_review_v2942.json`
- `official_undergraduate_catalog_2026.json`
- `major_name_model` 大模型核心
- 易混专业完整 `detected_pairs` 大模型

这些改为后台空闲加载或展开详情时加载。

### 2. 易混专业改为轻量索引
启动只加载 recordIndex，用于保留 `hasConfusableMajorV2946()` 的布尔判断能力，避免 A/B/C 中完全丢掉易混提醒。

完整 detectedPairs 只在用户展开易混专业详情时加载。

### 3. 详细卡片真懒加载
专业学科、易混专业、路径取舍、规则明细继续使用 shell 方式，点开后再生成内容。

### 4. 第 6 步布局修正
- 禁用 `#candidateArea.step-card:before`，避免伪标签作为 grid item 参与排版。
- 自选池 Markdown 导出按钮不再插入 `#candidateArea` 根节点，改插入右侧自选栏。
- 详细候选默认单列，超宽屏才允许两列。

### 5. Observer 收敛
Markdown 导出按钮不再全 body 观察，只监听：

- `.family-read-actions-v291`
- `#candidateArea`
- `ln:cards-rendered`
- `ln:abc-rendered`

## 不变部分

- 不改 `compute-pipeline`
- 不改 `filter-engine`
- 不改 `plan-engine`
- 不改地域 hard
- 不改兴趣真实命中规则
- 不改原始投档数据
- 不改一分一段数据
- 不改 closure5fix1 的 A/B/C 业务裁决公式
