# V3.0.0.rc1.fix3｜资格型计划默认过滤与入口同步版

## 修复背景

RC1 真实页面试用中发现：当用户同时输入“650 分”和“56548 位”时，系统会用分数判断为“625+ 高分平台段”，但又按 56548 位加载 500 分附近候选，导致 A/B/C 推荐口径分裂。

这属于 P0 阻断问题：分数和位次明显冲突时，不允许继续生成推荐。

## 本版修复

1. Step1 增加分数/位次一致性校验。
2. 同时输入分数和位次时，会用 2025 辽宁物理类一分一段换算参考位次并判断偏差。
3. 明显冲突时，阻止继续加载和进入后续步骤，并提示重新确认。
4. 分数段策略改为优先使用 effectiveRank / effectiveScore，不再让 raw score 和 raw rank 各自影响不同链路。
5. 决策上下文、A/B/C、详细卡片、导出报告统一读取 effectiveInput。
6. 导出报告新增“输入口径”：显示原始输入与系统采用口径。
7. 条件变化对照隐藏 0→0 的无效项，避免报告出现无意义对照。
8. Debug 一键总检新增冲突输入回归：56548 / 650 必须拦截，56548 / 500 必须通过。

## 不改内容

- 不改 Step4 家庭路径权重。
- 不改 Step5 A/B/C 方案包逻辑。
- 不改 Step6 候选生成规则。
- 不改证据等级体系。
- 不启用旧 compute 替换。
- 不覆盖旧 /fenxi/index.html。
